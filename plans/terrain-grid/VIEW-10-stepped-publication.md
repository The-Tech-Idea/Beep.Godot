**Type:** enhancement + duplication close-out · **Area:** `TerrainRendererComponent` (publication contract), `TerrainWorldComponent.Generation.cs` (one `_publication`), `TerrainTileRendererComponent` + `TerrainTransitionLayerComponent` (stepped build), `TerrainIsometricRendererComponent` (stepped build), `TerrainPaintedRendererComponent`/`TerrainIsometricAutotileRendererComponent` (adopt the contract over their existing machinery) · **Status:** proposed 2026-09-15 · **Effort:** M (3–4 days) · **Risk:** medium (every view's publication path moves; the pending-layer swap must keep the retained-display rule)

## Gap

1. **Two views publish stepped, two stall.** `TerrainWorldComponent.Generation.cs` `_Process` (`:83-206`): Painted begins an off-thread snapshot (`:154-167`) and `ContinuePaintedPublication` steps it (`:208-239`); IsometricAutotile calls `RequestRebuild` (`:168-180`) and `ContinueAutotilePublication` waits (`:241-272`); Tiles and Isometric fall through to `Draw(...)` inline (`:181`). `TerrainTileRendererComponent.Rebuild` (`:268-312`) refreshes every transition layer synchronously (`:303-307`); `TerrainIsometricRendererComponent.Rebuild` (`:371-512`) runs the depth BFS, the summit sort and the per-cell stack in one call — the renderer whose per-cell cost "compounds hardest of any renderer in the addon" by its own comment (`:391-396`). On Huge (128×80) that is one frame stall behind the loading screen; above ENH-07's 65 536-cell threshold it is unusable, and the block view is a shipped view (owner's decision, 2026-09-15).
2. **The orchestrator carries one field and one continue method per stepped view.** `_publicationPainter`/`_publicationAutotile` (`:31-32`), two near-identical source-validation blocks (`:213-219`, `:246-255`), two cancellation pairs in `CompletePublication`/`RetireGeneration` (`:308-311`, `:328-331`), two progress labels (`:164`, `:178`), and `Draw`'s `preparedAutotile` flag (`Drawing.cs:32`, `:136-140`). 3. **DUP-01's remainder is exactly this contract.** DUP-01 landed the rebuild coalescer (`TerrainRendererComponent.cs:29-102`) and is `PARTIALLY IMPLEMENTED 2026-09-09`; its `Draw()` rewrite was investigated and declined (`DUP-01-terrain-renderer-lifecycle-contract.md:16-19`), and source resolution was deferred to ENH-01, which has since landed the typed signal the base consumes (`:90-94`). ## Design

1. **DUP-01 close-out — the publication contract on the base.** `TerrainRendererComponent` gains `public virtual bool BeginPublication()` (default `false`: "I build synchronously in `Rebuild()`"), `public virtual bool StepPublication(int budget)` (true when published), `public virtual void CancelPublication()`, `public bool IsPublishing`, `public string PublicationStage`, `public float PublicationProgress` (0..1), `public ulong PublicationRevision`, and `ShowPrepared()` (today autotile-only, `:309-313`). Painted implements the three over its snapshot preparation; IsometricAutotile over `RequestRebuild` and its enumerator (`StepPublication` drives `_build` in place of `_Process`, `:346-371`, while a publication is in flight; `_Process` remains for renderer-initiated time-sliced rebuilds; `RequestRebuild/CancelRebuild/IsRebuilding` stay public for `terrain_autotile_staleness_probe.gd`). `Generation.cs` keeps **one** `TerrainRendererComponent? _publication` in place of `:31-32`; after `PublishField` (`:151-153`) it sets the active view's bounds and asks `BeginPublication()` — true → `_publication = view`, stage `"Preparing <view> terrain"`, return; false → `Draw(...)` as today (`:181`). One `ContinuePublication(job)` replaces `:208-272`: the shared validation (instance valid, in tree, its path still resolves to it, `Projection` unchanged, generator and cells unchanged), `StepPublication(PublicationCellsPerFrame)` (the budget already used at `:138`, `:220`), progress from `PublicationProgress`, the cancelled-versus-failed rule (`PublicationRevision` unchanged and no `reason` in the diagnostics, `:257-259`), `ActiveViewProblem()` (`:260-261`), then `Draw(BuiltSize, queueCollision: true, prepared: true)`. `CompletePublication`/`RetireGeneration` call `_publication?.CancelPublication()` once. DUP-01's `Configure(origin, size, visible)` is still not taken: `Draw()` assigns bounds and visibility explicitly and that orchestration was kept on purpose (`DUP-01:16-19`).
2. **Tiles, stepped.** `BeginPublication()` returns true above the same 65 536-cell threshold the autotile view uses (`:195`), so every existing scene and probe keeps today's inline path. Steps: `EnsureLayers`; per transition layer a `RefreshTransitionsSteps()` iterator yielding one dual-grid row per step (`PaintDualCell`, `TerrainTransitionLayerComponent.cs:185-192`) or, on the terrain-set path, VIEW-08's `Build` batches; `ApplyGroundDetail`; `EnsureWaterSurface` last (`:458-504`; the coast resolve `:479` stays one call — ENH-05 owns splitting its upload). Rows are painted into **pending** display layers and swapped by `TileMapData` on publish (the autotile pattern, `:411-421`, `:496-499`), so a cancelled build keeps the last terrain on screen — the retained-display rule the 2026-09-15 fix and `terrain_library_pack_probe.gd` require. `_paintDiagnostics` is set at publish.
3. **Isometric, stepped.** Above the threshold: the two full passes first, one row per step — water depth (VIEW-05's `CellDistances` replacing `MeasureWaterDepth`, `:669-709`) and `MeasureSummitFloor` (`:636-661`) — then per row the extent, river vertices, seabed and stack of `:424-508` into pending level layers and a pending seabed; `RebuildRivers` (`:1046-1079`) and `EmitSignal(SurfaceRebuilt)` (`:511`) only at publish, so the isometric feature renderer that follows the surface (`Drawing.cs:35`, `:44`) rebuilds its props once against a finished surface. `Rebuild()` becomes `BeginPublication` + drain, so `iso_layers`, `terrain_iso_*` and `terrain_surface_height_probe` see no change.
4. **Stage names.** `"Preparing painted terrain"`, `"Preparing tile terrain"`, `"Preparing isometric terrain"` (both isometric views; `terrain_world_iso_publication_probe.gd:58` keys on that string). `TerrainLabComponent.OnGenerationProgress` (`TerrainLabComponent.cs:198-206`) is unchanged.
5. Docs: `docs/terrain-engine/TerrainWorldComponent.md` (publication), a new `docs/terrain-engine/TerrainRendererComponent.md` (the base has no page), and DUP-01's status line → implemented, naming this item and restating that the `Draw()` loop and per-renderer source resolution stay declined.
