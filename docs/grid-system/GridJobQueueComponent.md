# GridJobQueueComponent

`GridJobQueueComponent` is the central job registry for the grid system's builder/RTS/farming/tactics/settlement work loop: clear land, build road, harvest tile, deliver resource, inspect a cell. It owns the full lifecycle of a job (Queued → Claimed → Completed, or Cancelled at any point before Completed) keyed by a generated string id, and knows nothing about TileMap, terrain, or rendering — jobs are just a cell, a kind, a priority, and a duration. Workers, tool actions, and selection commands all create and consume jobs through this one component rather than each tracking work state themselves.

It exists as a standalone `Node` with no NodePath dependencies of its own specifically so nothing else in the grid system has to be present for it to function — the class doc comment states the intent directly: "Workers claim jobs by id and complete, release, or cancel them without the queue depending on TileMap." `RequeueClaimedJobsOnLoad` defaults to `true` for a documented reason rather than convention: worker ids are built from the instance id (see `GridWorkerComponent.WorkerId`), which no reload reproduces, and workers do not persist which job they were mid-way through — so a job saved as `Claimed` would, on load, belong to a worker that can never claim it back and would sit claimed forever if not requeued. `UniqueCellKind` (default on) prevents `AddJob` from stacking a second identical-kind job onto a cell that already has one open, which is what lets callers like `GridSelectionJobCommandComponent` queue a whole selection repeatedly without needing to de-duplicate themselves.

## Public API
- `enum GridJobState { Queued, Claimed, Completed, Cancelled }` — the job lifecycle.
- `string AddJob(Vector2I cell, string kind = "work", float workTurns = -1f, int priority = 0)` — creates a job (or returns the existing open job's id if `UniqueCellKind` and one already matches cell+kind); normalizes `kind` (lowercase, spaces→underscores) and falls back to `EffectiveDefaultWorkTurns` when `workTurns` isn't positive/finite. Work is in **turns**, the grid's one unit — the same unit as `BuildTurns`, `DurationTurns` and `CycleTurns`; `GridWorkClockComponent` decides what a turn is in the game's own time. The queue never ticks and never divides by a frame delta, so the value stays a float for sub-turn resolution.
- `bool CancelJob(string id, string reason = "cancelled")` — cancels a Queued or Claimed job, emits `JobCancelled`, and removes it from the dictionary if `RemoveCancelledJobs`.
- `string ClaimNextJob(string workerId, Vector2I workerCell, Array<string>? allowedKinds = null)` — picks the best queued job by highest priority, then nearest Manhattan distance, then id order as a tiebreaker; a non-empty `allowedKinds` restricts which kinds a worker will even consider, "so a boat claims 'fish' jobs, a truck everything else, and neither churns on work it can never reach."
- `bool ClaimJob(string id, string workerId)` — claims one specific job by id if it is still Queued.
- `bool ReleaseJob(string id, string workerId = "")` — returns a Claimed job to Queued; if `workerId` is given it must match the current claimant.
- `bool CompleteJob(string id, string workerId = "")` — marks a job Completed, emits `JobCompleted`, removes it if `RemoveCompletedJobs`.
- `bool HasJob(string id)`, `Vector2I GetJobCell(string id)`, `string GetJobKind(string id)`, `string GetJobClaimedBy(string id)`, `float GetJobWorkTurns(string id)`, `GridJobState GetJobState(string id)` — lookups; missing-id sentinels are `(int.MinValue, int.MinValue)` for cell, `""` for strings, and **`GridJobState.Cancelled`** (not a distinct "unknown" value) for state.
- `string FindClaimedJobId(string workerId)` — a direct scan over the live job objects (no `Dictionary` marshalling) for a single on-demand lookup. `Dictionary<string,string> GetClaimedJobIdsByWorker()` — every currently-`Claimed` job's id keyed by claiming worker id, one pass, for a caller resolving many workers at once (a HUD refresh) instead of calling `FindClaimedJobId` per worker.
- `void ReportProgress(string jobId, float remainingTurns)` / `float GetJobProgress01(string jobId)` — job progress as a fact the QUEUE owns: whoever is executing a job (`GridWorkerComponent.AdvanceWork` does, on every work tick; a custom `IWorker` implementation is expected to as well) reports how much work is left, and `GetJobProgress01` derives `1 - RemainingTurns/WorkTurns` (clamped to `[0,1]`, `0` for an unreported or unknown job). This is what lets the construction-in-progress effect components (`GridBuildProgressBarComponent` and siblings) show progress without ever having to locate which worker holds a given job.
- `bool SetJobApproachCell(string id, Vector2I approachCell)` / `Vector2I GetJobApproachCell(string id)` — the cell a worker should STAND ON to do the job, the job cell itself by default. A build site sets it to a cell just outside its footprint (`GridBuildSiteComponent.ApproachCellFor`): the footprint's own cells are blocked by the placed `GridObjectComponent`, so a worker sent to the job cell with `AllowedBlockedGoal` off fails with `no_path` and drops the job. Round-trips through `GetJobs`/`LoadJobs` as `approach_cell`.
- `int QueuedCount`, `int ClaimedCount`, `int CompletedCount` — each a fresh O(n) scan of `_jobs`.
- `void ClearJobs()` — drops every job and re-emits `QueueChanged`.
- `Array<Dictionary> GetJobs()` / `void LoadJobs(Array jobs, bool clearExisting = true)` — save/load round-trip; `LoadJobs` skips malformed entries (missing id, unparseable cell) rather than throwing, applies `RequeueClaimedJobsOnLoad`, and replays `TrackNextJobNumber` on every loaded id so freshly generated ids never collide with restored ones.
- `float EffectiveDefaultWorkTurns` — `DefaultWorkTurns` clamped to a sane positive, finite value.
- Signals: `JobAdded(id, kind, x, y)`, `JobClaimed(id, workerId)`, `JobReleased(id, workerId)`, `JobCompleted(id, workerId)`, `JobCancelled(id, reason)`, `QueueChanged(queued, claimed, completed)`.

## Dependencies

None outward — this component resolves no NodePaths and calls into no other grid-system type. Within this batch it is depended on rather than depending: `GridJobEffectComponent` subscribes to its `JobCompleted` signal and reads jobs back via `GetJobKind`/`GetJobCell`; `GridWorkerComponent` claims, releases, and completes jobs through it; `GridWorkerSpawnerComponent` wires a newly spawned worker's `JobQueuePath` to it; `GridSelectionJobCommandComponent` and `GridToolActionComponent` both call `AddJob` to turn a selection or tool click into work.

## Notes

- `GetJobState` returns `GridJobState.Cancelled` for an id that was never a job at all, not a distinct "unknown" state — a caller that only checks `!= Cancelled` to decide whether to keep polling would treat a bad id the same as a job that ran and was cancelled.
- `FindOpenJobAt`, `ClaimNextJob`, and `Count` are each a linear scan of every job in the dictionary; fine at the scale this addon targets, but there's no cell→job index, so `AddJob`'s de-dup check and every claim scan the whole queue.
- The private `GridJob` class mixes an immutable identity (`Id`, `Kind`, `Cell`, `Priority`, `WorkTurns`, all init-only) with mutable lifecycle state (`State`, `ClaimedBy`, and `RemainingTurns` for `ReportProgress`, initialized to `WorkTurns` so a never-reported job reads as 0% rather than undefined).
- No accepted-but-unread export: every export (`UniqueCellKind`, `RemoveCompletedJobs`, `RemoveCancelledJobs`, `RequeueClaimedJobsOnLoad`, `DefaultWorkTurns`) is read somewhere in the same file.
- Saved under `work_turns` in `GetJobs`/`LoadJobs`. The field was called `WorkSeconds` (key `work_seconds`) while the work clock already fed it turns; `tests/addon_contract_scan.ps1` now forbids any grid file measuring work in seconds again, the dispatch board's real-time showcase tween excepted.
