Design Rules

  • Author visible Godot nodes at design time and attach behavior components to them.
  • Use exported NodePath fields to bind labels, buttons, panels, roots, and layers.
  • Use runtime generated controls only as an explicit fallback for prototypes or tests.
  • Use TerrainPaintedRendererComponent as the broad terrain base and keep TileMap layers only where cell detail or collision is needed.
  • Keep grid state cell-based: isometric projection changes how cells are drawn, not how jobs, resources, workers, or saves are modeled.
  • One owner per fact: what a resource is lives in the shared ResourceCatalog; which cell holds a deposit lives on the node standing there.

Terrain And Projection

TerrainGeneratorComponent builds the deterministic terrain field and writes one terrain kind per cell into GridCellDataComponent at build time. TerrainPaintedRendererComponent draws that terrain as one continuous shader-blended surface, so the tile layers above it stay free for collision, roads, crops, and feedback.

TerrainDataLayersComponent publishes the generated map as invisible TileMapLayers carrying custom tile data (terrain, resource, feature, relief, is_water, passable, continent, start_position) plus native per-ground collision and navigation. Point GridResourceScatterComponent.DataLayersPath at it so deposits land where the map actually put resources; navigation, placement, and tools accept the same DataLayersPath to read terrain kinds straight from the generated map.

GridProjectionComponent is the shared world/cell conversion layer for both top-down and isometric scenes.

GridNavigationComponent is cell-based A* over cell flags, blocked terrain kinds, placement occupancy, and GridRoadComponent cost multipliers. Shallow water is wadeable at a cost for units but blocked for building by default.

GridTileMapLayerBridgeComponent mirrors cell and road state into a Godot TileMapLayer when the scene needs tile collision or detail. GridCellOverlayComponent draws cell-state fills before a project has tile art for every state.

Selection, Tools, And Placement

GridSelectionComponent handles hover, click, and rectangle selection. GridInteractionModeComponent routes clicks across select, inspect, tool, build, and disabled modes.

GridInteractionModeBarComponent, GridInteractionStatusComponent, and GridInteractionCursorComponent expose mode, feedback, and valid/invalid cell outlines.

GridToolActionComponent can use CellDataPath and NavigationPath to reject direct clear, hoe, plant, or queue-job actions on water, lava, disallowed terrain, or out-of-bounds cells before mutating the grid. Planting charges the crop's seed item from the wallet (ConsumeSeedsFromWallet), and crops with a regrow interval re-arm after harvest instead of clearing. The full occupancy-ownership matrix — which component owns each blocked/occupied fact — is in the Markdown guide.

GridPlacementComponent, GridBuildDefinition, GridBuildCatalogComponent, GridBuildToolbarComponent, and GridBuildSiteComponent cover build preview, resource cost, footprint reservation, terrain placement rules from GridCellDataComponent, navigation blocking through GridNavigationComponent, and build-site jobs.

Resources, Jobs, Crops, And Production

GridResourceWalletComponent stores primitive dictionary balances through StartingResourceAmounts. GridResourceAmount is used for build and recipe costs. The shared ResourceCatalog defines what each resource id is, for the generator and the economy alike.

GridResourceBarComponent, GridResourceNodeComponent, and GridResourceScatterComponent expose HUD balances, gatherable objects, and seeded or map-driven resource deposits. Resource nodes can reserve placement cells until depleted; with a catalog assigned, a node takes its gather rules from the definition for its id.

GridJobQueueComponent, GridJobBoardComponent, GridJobEffectComponent, and GridSelectionJobCommandComponent turn selected cells into worker jobs and apply completed jobs to the world, including gathering the resource node on a cleared cell.

GridCellDataComponent, GridCropDefinition, GridCropCatalogComponent, GridCalendarComponent, and GridCalendarHudComponent cover Stardew-style crops and dates.

GridProductionRecipe, GridProductionComponent, and GridProductionPanelComponent cover machine inputs, outputs, progress, pause, resume, and cancel. GridDispatchBoardComponent with GridDispatchTaskDefinition resources runs the lighter dispatch-a-vehicle loop for showcase scenes.

Workers And State

GridNavigationComponent, GridRoadComponent, and GridPathFollowerComponent move workers through the cell world. Set CellDataPath on navigation and roads so they read blocked cell flags, impassable terrain kinds, and terrain movement costs from the same cell model that renders the map.

GridWorkerComponent, GridWorkerSpawnerComponent, GridWorkerSpawnerPanelComponent, and GridWorkerStatusPanelComponent provide the base-to-worker loop. Wire CellDataPath and PlacementPath on the spawner so base/depot spawns reject out-of-bounds cells, blocked cell flags, impassable terrain kinds, and occupied placement cells before creating a unit.

GridObjectComponent and GridObjectInspectorComponent make buildings, props, units, and resources selectable, including object kind/category and description text. Authored grid objects can reserve their placement and navigation footprint by wiring PlacementPath, NavigationPath, and ReserveFootprintOnReady. GridWorldStateComponent captures cells, roads, jobs, placement, navigation blocks, selection, and authored object state for saves, then reapplies object footprint reservations on restore.

GridObjectiveDefinition, GridObjectiveTrackerComponent, GridObjectivePanelComponent, and GridObjectiveEventBinderComponent track goals and advance them from completed jobs, builds, gathers, and production cycles.

HUD And UI Kit Practice

Use authored Control, Button, and Label nodes with KitPanelContainer, KitPushButton, KitLabel, KitLabelValue, KitToast, KitTooltip, and KitSpeechBubble, and ResourceBadgeComponent for game-styled resource readouts. Bind component paths to those nodes instead of letting systems create hidden runtime panels.
