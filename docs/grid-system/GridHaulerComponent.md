# GridHaulerComponent

The default transporter: a vehicle that accepts hauls dispatched by `GridTransportManagerComponent`, drives to the pickup cell, drives to its depot, and pays the load into the wallet (or a wired storage's load port) on arrival. Attached under a vehicle body (`Node2D` or `CharacterBody2D`) beside a `GridPathFollowerComponent`, with `DepotCell` pointing at the drop-off. It implements `ITransporter`, so it is both a load port and an unload port and can be handed cargo by, or hand cargo to, anything else in the logistics layer (a storage tank, another hauler, a pipeline segment).

Like `GridExtractorComponent`, it is explicitly a default rather than the only way to build a transporter: `GridTransportManagerComponent` accepts any `Node` that answers the `IGridTransporter` shape, and this component exists so transport works out of the box. `AllowedResourceIds` filters what it will carry — the doc comment's example is "an oil tanker is not a log truck." `TransportRate` is the fleet's pecking order, in units per TURN — the same unit `GridTransportChainComponent.FlowRatePerTurn` carries, or the ranking would compare two different things: the manager offers a haul to the fastest accepting transporter first, so a pipeline (high rate) outranks this truck, which outranks a mule.

## Public API
- `bool RequestHaul(Vector2I fromCell, string resourceId, int amount)` — accepts a haul job. Loads the full `amount` into its own hold first (all-or-nothing: a partial load has nowhere to put the remainder, so it un-loads and refuses if `Load` returns less than asked), then asks its `GridPathFollowerComponent` to move to `fromCell`. Returns `false` (undoing the load) if busy, the amount is invalid, the resource isn't accepted, there's no path follower, or the follower can't path.
- `enum HaulerState { Idle, MovingToPickup, MovingToDepot }`; `HaulerState State { get; }`, `bool IsBusy { get; }` (`State != Idle`).
- `string CarryingResourceId { get; }`, `int CarryingAmount { get; }`, `int CurrentLoad { get; }` — current cargo.
- `bool CanAccept(string resourceId)` — true if `AllowedResourceIds` and `AllowedResourceTags` are both empty (carries anything); otherwise delegates to `AcceptsResourceType`, identical shape and reasoning to `GridStorageComponent`'s (see that file's doc) - exact-id match wins, else a `Catalog`-backed tag match, else reject.
- `int Stored(string resourceId)`, `Godot.Collections.Array<string> StoredIds()`, `int Load(string resourceId, int amount)`, `int Unload(string resourceId, int amount)` — the `ILoadPort`/`IUnloadPort` implementation over the single-resource cargo hold (capacity `Capacity`). `Load` refuses a second resource id while cargo is already held.
- `bool TryDeliverCargo()` — empties the hold at the destination: into `DepotStoragePath`'s load port via `GridPorts.Transfer` if wired (what doesn't fit *stays in the hold* and is retried — backpressure, not loss), else into the wallet directly. Returns true once the hold is empty.
- `void AdvanceWork(float turns)` — the haul step, in TURNS: manager registration retry and arrival detection. Bound to `GridWorkClockComponent.WorkTick` (found via `WorkClockPath`, or scene-wide when it is empty); with no work clock anywhere `_Process` drives it at one turn per second.
- `void Tick(double delta)` — the old entry point, kept: advances the real-time delivery retry by `delta` seconds and the haul by the same span converted to turns, for an orchestrator driving the truck directly.
- Exports: `TransportManagerPath`, `PathFollowerPath`, `ResourceWalletPath`, `WorkClockPath`, `DepotStoragePath` (all `NodePath`), `RegisterOnReady`, `DepotCell` (`Vector2I`), `AllowedResourceIds`, `Catalog` (`ResourceCatalog?`, optional), `AllowedResourceTags`, `Capacity`, `TransportRate`, `DeliveryRetrySeconds`.
- Signals: `HaulAccepted(int x, int y, string resourceId, int amount)`, `HaulDelivered(string resourceId, int amount)`, `HaulFailed(string resourceId, int amount, string reason)`.

## Dependencies
- Resolves: `GridTransportManagerComponent` (`TransportManagerPath`, explicit or scene-wide `FindComponent` fallback), `GridPathFollowerComponent` (`PathFollowerPath`, explicit or non-recursive sibling search on its own parent), `GridResourceWalletComponent` (`ResourceWalletPath`, explicit or scene-wide fallback), a generic `Node` at `DepotStoragePath` (explicit-only, no fallback — matches the file's own comment that `DepotStoragePath` is "optional").
- Registers itself with `GridTransportManagerComponent.Register` on `_Ready` (if `RegisterOnReady`) and unregisters on `_ExitTree` — this batch.
- Calls `GridPorts.Transfer` (outside this batch, in `GridPorts.cs`) for depot delivery, which is the same primitive `GridTransportManagerComponent.Transfer` and `GridTransportChainComponent`'s link hand-off use.
- `RequestHaul` is called by `GridTransportManagerComponent.RequestHaul` (this batch) as the dispatch target, and directly by `GridExtractorComponent.DeliverYield` (this batch) when `DeliverVia == TransportManager` and the manager assigns this hauler.
- Reads `_follower.IsMoving` and calls `_follower.MoveToCell(Vector2I)` on `GridPathFollowerComponent` (outside this batch).

## Notes
- `Catalog`/`AllowedResourceTags` link this component to `ResourceCatalog`/`ResourceDefinition` (`ecs/terrain/`, see `docs/resource-system/DEVELOPER_GUIDE.md`), added at the same time and in the identical shape as `GridStorageComponent`'s - see that file's notes for the full reasoning.
- `DeliveryRetrySeconds` stays in REAL SECONDS while everything else here moved to turns, and `AdvanceDeliveryRetry` is driven by the frame delta from `_Process` on both time axes. Knocking at a full depot is polling for space somebody else has to free, not work this hauler is doing — a turn-based game that stopped retrying between turns would sit on held cargo with the depot already drained. It is the reason `_Process` stays enabled even when a work clock is driving the haul.
- The idle-state retry loop (`_retryClock` against `DeliveryRetrySeconds`) only engages "if `_cargoAmount > 0 && !DepotStoragePath.IsEmpty`" — a hauler stuck with cargo and delivering to the *wallet* (no `DepotStoragePath`) has no retry path at all, but that's moot in practice: wallet delivery in `TryDeliverCargo` never fails (`AddAmount` has no capacity to refuse), so cargo destined for the wallet always drains to zero the moment `Deliver` runs and never reaches the idle state with cargo still held.
- `Arrived()` on `MovingToPickup` falls back to delivering cargo "where it stands" (with `"no_path_to_depot"` reported via `HaulFailed`) if the follower can't path to `DepotCell` — same "never lose the load" posture as `GridExtractorComponent`'s buffer-overflow-to-wallet and `GridTransportChainComponent`'s backpressure.
- Structurally near-identical to `GridExtractorComponent` in this batch: both are `[Tool][GlobalClass] : GameplayComponent`, both implement a port pair, both self-register with a manager on `_Ready`/unregister on `_ExitTree`, both advance on the grid work clock through `GridWorkClockBinding` and keep a public `Tick(double)` alongside their `_Process` fallback. This is the established shape for a "default participant" component in this system, not incidental duplication — the two serve genuinely different roles (source vs. mover) and share no code, only the pattern.
