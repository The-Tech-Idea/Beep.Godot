# GridResourceScatterComponent

Gameplay/editor component: seeded generator that populates `GridResourceNodeComponent` props (trees, rocks, crates, or other gatherables) across a rectangular bounds, so a farm/settlement/survival map gets its resource deposits without hand-placing every one.

It supports two independent placement strategies, chosen automatically per-call by whether `DataLayersPath` resolves. Pointed at a `TerrainDataLayersComponent`, it places deposits exactly where the generated map's published resource layers say a resource is (iron in the hills the generator made, fish in its shallows) — the design comment explains this reads the *published* layers rather than the generator itself specifically because the generator is a build-time-only object, while a saved/loaded map only carries its tile layers. Left unset, it falls back to a seeded random density scatter of one `ResourceId` — the right behavior for an authored map with no generated terrain. A second design note (on `IncludeLiquidResources`) explains why liquid-stratum resources like fish skip the normal land-terrain veto: they are meant to sit on water cells and be gathered by boat workers, while underground deposits never get a walk-up node at all because they're building-extracted.

## Public API
- `ResourceScatterRebuilt(count)` signal — emitted at the end of `RebuildScatter()`.
- `[Export] NodePath GridPath/ResourceRootPath/PlacementPath/CellDataPath/DataLayersPath` — resolved lazily; `ResourceRootPath` defaults to `GetParent()` when empty.
- `[Export] bool IncludeLiquidResources` — see above.
- `[Export] ResourceCatalog? Catalog` — the same catalog the generator and `GridResourceNodeComponent` use; a data-layer resource id that the catalog doesn't `Contains()` is treated as not worth a deposit.
- `[Export] NodePath ResourceWalletPath/JobQueuePath` — wired onto each generated node.
- `[Export] PackedScene? ResourceScene` — fallback scene when the catalog's `ResourceDefinition.NodeScene` for the placed id is null.
- `[Export] bool GenerateOnReady/ClearPreviousGenerated/AvoidOccupiedCells/AvoidCellDataBlocked/AvoidBlockedTerrainKinds/MarkGeneratedCellsOccupied`.
- `[Export] Godot.Collections.Array<string> BlockedTerrainKinds` (defaults to `GridTerrainRules.DefaultBlockedTerrainKinds()`) / `AllowedTerrainKinds`.
- `[Export] int Seed`, `Vector2I BoundsOrigin/BoundsSize`, `float Density`, `int MaxNodes` — random-scatter-path parameters.
- `[Export] string ResourceId`, `int MinAmount/MaxAmount/AmountPerGather`, `string GatherJobKind`, `float GatherSeconds`, `int GatherPriority` — fallback economics for the random-scatter path (or for a data-layer id the catalog doesn't define).
- `[Export] bool SetZIndexFromY` — sort generated nodes by vertical position.
- `Vector2I EffectiveBoundsSize`, `float EffectiveDensity`, `int EffectiveMaxNodes`, `int EffectiveAmountPerGather`, `float EffectiveGatherSeconds`, `string EffectiveResourceId`, `string EffectiveGatherJobKind` — clamped/defaulted read accessors over the raw exports.
- `int RebuildScatter()` — clears previously generated children (if configured), walks candidate cells, instantiates/configures a resource node per cell up to `MaxNodes`, positions it via the grid, tags it with scatter metadata, optionally reserves its cell, and returns the count placed.
- `int ClearGenerated()` — removes only children tagged as generated by this component; returns the count removed.
- `Godot.Collections.Array<Vector2I> PreviewCells()` — the same candidate-cell enumeration `RebuildScatter()` would place on, without instantiating anything (editor preview use).

## Dependencies
- Resolves `GridProjectionComponent`, `TerrainDataLayersComponent`, `GridPlacementComponent`, and `GridCellDataComponent` via NodePath or `EntityComponent.FindComponent`.
- Reads `TerrainDataLayersComponent.ResourceAt(cell)` / `LiquidResourceAt(cell)`, and `ResourceCatalog.Find`/`Contains`.
- Calls `GridTerrainRules.Normalize/IsAllowed/MatchesAny/DefaultBlockedTerrainKinds` and `GridCellDataComponent.HasFlag`/`GetTerrainKind` to veto candidate cells.
- **Creates and configures `GridResourceNodeComponent` instances (this batch)**: sets `UseExplicitCell`, `Cell`, `ResourceId`, `Catalog`, `GatherPriority`, `MarkCellOccupiedOnReady`; sets `Amount`/`AmountPerGather`/`GatherJobKind`/`GatherSeconds` on it *only* when `Catalog.Find(resourceId)` is null (see Notes); rewires the node's own `GridPath`/`PlacementPath`/`ResourceWalletPath`/`JobQueuePath` to relative NodePaths via `RelativePathTo`; subscribes to the node's `Depleted` signal to release the reserved cell.
- Not established from this batch alone: nothing among the other six files calls `RebuildScatter()`, `ClearGenerated()`, or `PreviewCells()` — the caller (editor tool button, map-generation orchestrator) is outside this batch.

## Notes
- The `resource.Catalog = Catalog; if (Catalog?.Find(resourceId) is null) { ... }` block is explained by its own comment as a fix for an accepted-but-overwritten value: this component's `MinAmount`/`MaxAmount`/gather exports used to be written onto every generated node regardless of the catalog, only for `GridResourceNodeComponent.ApplyCatalogDefinition()` to silently overwrite them one frame later whenever the catalog defined that id. They are now written only for the id the catalog does *not* define, which is the one case they're actually the answer.
- `ClearGenerated()` only removes direct children of the resolved root (`_resourceRoot ?? this`) carrying the `grid_resource_scatter_generated` meta flag — hand-placed nodes, or nodes generated by a *different* scatter instance into the same root, are left alone; nodes generated into a different root than the current `ResourceRootPath` are also left untouched even if this same component generated them under a prior configuration.
- `CandidateCells()` is a single method serving both code paths (data-layer-driven exact placement and random density scatter) rather than two separate methods — the branch is a straightforward early-continue on `_dataLayers is not null`, not a duplicate implementation.
