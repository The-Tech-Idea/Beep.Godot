# GridExtractorComponent

The default extractor: a placed building that works the deposit under it — a derrick, a mine shaft, an offshore platform, a colony ice extractor. Attached under a building scene alongside its `GridObjectComponent`, it waits (by default) for the building's `Complete` flag, binds to the deposit beneath its footprint once complete, validates it can work it, and draws it down cycle by cycle into the wallet (or wherever `DeliverVia` sends it) until the deposit is worked out. It implements `IExtractor`, which makes it both an `ILoadPort` and `IUnloadPort` — its own output buffer is a port the rest of a logistics chain connects to directly.

It is explicitly a *default*, not doctrine: the doc comment is direct that how extraction feels is the game's decision, and the real contract the system depends on is `GridSubsurfaceStoreComponent`'s three methods (`ResourceIdAt`, `RemainingAt`, `Draw`), which any script — C# or GDScript — can call without going through this component at all. Two `protected virtual` hooks exist for the parts of "extraction" that vary by game: `DepositBlockReason` (what may be worked — tech trees, permits, licence blocks; the default enforces the `ReachDepth` ladder and a deposit's authored `ExtractorBuildId`) and `DeliverYield` (where the yield goes — a local buffer, a truck, a silo; the default follows `DeliverVia`). Several "extractor types" in a game are meant to be nothing more than several build definitions, each with its own scene carrying its own configured or subclassed extractor.

A `Fluid` or `Gas` deposit is treated as one connected reservoir (`ExpandToReservoir` flood-fills 4-connected cells sharing the resource id, capped at 4096 cells) so a well drains the whole contiguous field the way an oil well actually behaves; a `Solid` deposit stays cell-local — a mine only gets what is directly under its footprint.

## Public API
- `bool TryBind()` — finds the deposit under the footprint and starts the pump; safe to call again after a stop. Returns `false` (via `Stop`, emitting `ExtractionStopped`) when there's no store, no deposit, or the deposit is blocked.
- `void StopExtraction(string reason = "stopped")` — stops extraction and emits `ExtractionStopped(reason)` (unless already stopped and the reason is the default `"stopped"`, to avoid a redundant signal).
- `bool IsExtracting { get; }`, `string ActiveResourceId { get; }` — current pump state.
- `bool IsStalled { get; }` — true while `Buffer` delivery is shut in by a full output buffer; the deposit stays intact and extraction resumes on its own once the chain drains the buffer.
- `int CurrentLoad { get; }` — units currently in the output buffer.
- `bool CanAccept(string resourceId)`, `int Load(string resourceId, int amount)`, `int Unload(string resourceId, int amount)`, `int Stored(string resourceId)`, `Godot.Collections.Array<string> StoredIds()` — the `ILoadPort`/`IUnloadPort` implementation over the extractor's own single-resource output buffer (capacity `BufferCapacity`).
- `float CurrentCycleTurns()`, `int CurrentAmountPerCycle()` — current per-cycle timing/amount, for rate displays and for `GridExtractionManagerComponent.EstimatedRatePerTurn`.
- `void AdvanceWork(float turns)` — the extraction step, in TURNS. Bound to `GridWorkClockComponent.WorkTick` (found via `WorkClockPath`, or scene-wide when it is empty), so a cycle takes the same amount of world time on the turn axis and the real-time one. With no work clock anywhere the component self-ticks from `_Process` at one turn per second, which is what lets a template scene or a headless probe run without a game clock.
- `void Tick(double delta)` — the old entry point, kept: converts a frame delta to turns and calls `AdvanceWork`, so an orchestrator that steps extraction deliberately still can.
- `protected virtual string DepositBlockReason(ResourceDefinition? definition)` — HOOK: whether the deposit may be worked. Default checks `ReachDepth` against `definition.Depth`, and (if the catalog resolved a definition) the resource's `ExtractorBuildId` against this building's `ObjectId`; falls back to the data layers' published depth band when there's no catalog entry.
- `protected virtual void DeliverYield(string resourceId, int amount)` — HOOK: where a cycle's yield goes, per `DeliverVia`. `Buffer` fills the output port and spills overflow to the wallet; `TransportManager` offers the load via `GridTransportManagerComponent.RequestHaul` and falls back to the wallet if unassigned; `Wallet` (default) pays the wallet directly.
- `protected IReadOnlyList<Vector2I> DepositCells { get; }`, `protected GridSubsurfaceStoreComponent? BoundStore { get; }` — exposed for subclasses running their own cycles.
- Exports: `DataLayersPath`, `SubsurfaceStorePath`, `ResourceWalletPath`, `GridPath`, `TransportManagerPath`, `ExtractionManagerPath`, `WorkClockPath` (all `NodePath`), `DeliverVia` (`ExtractorDelivery`), `BufferCapacity`, `ReachDepth` (`ResourceDepth`), `RequireCompleteBuild`, `AutoStart`, `CycleTurnsOverride`, `AmountPerCycleOverride`, `Catalog` (`ResourceCatalog?`).
- Signals: `ExtractionStarted(string resourceId)`, `ExtractionCycle(string resourceId, int amount, int remaining)`, `ExtractionStopped(string reason)`, `ExtractionStalled(string resourceId)`, `ExtractionResumed(string resourceId)`.
- `enum ExtractorDelivery { Wallet, TransportManager, Buffer }` — declared in this file, above the class.

## Dependencies
- Resolves (all `NodePath`, explicit-wire-first with a scene-wide `EntityComponent.FindComponent` fallback when the path is empty): `TerrainDataLayersComponent` (`DataLayersPath`), `GridSubsurfaceStoreComponent` (`SubsurfaceStorePath`), `GridResourceWalletComponent` (`ResourceWalletPath`), `GridProjectionComponent` (`GridPath`), `GridTransportManagerComponent` (`TransportManagerPath`), `GridExtractionManagerComponent` (`ExtractionManagerPath`) — the last two are in this batch.
- Finds a sibling `GridObjectComponent` non-recursively on its parent via `EntityComponent.FindComponent`, for `Footprint`/`Cell`/`Complete`/`ObjectId`.
- Calls `GridSubsurfaceStoreComponent.ResourceIdAt`, `.RemainingAt`, `.Draw` (this batch) — the actual pump.
- Calls `GridTransportManagerComponent.RequestHaul` (this batch) when `DeliverVia == TransportManager`.
- Calls `GridExtractionManagerComponent.Register`/`.Unregister` (this batch) on `_Ready`/`_ExitTree`.
- Calls `ResourceCatalog.Find` / reads `ResourceDefinition.Depth`, `.ExtractorBuildId`, `.GatherSeconds`, `.AmountPerGather`, `.Form` (outside this batch). `GatherSeconds` keeps its name — it is the shared resource catalog's, also read by the by-hand gathering path — but the extractor reads the number it carries as TURNS, the unit every timed grid subsystem measures in.
- Binds to `GridWorkClockComponent` through `GridWorkClockBinding` (`WorkClockPath`, or scene-wide when empty), the shared helper `GridProductionComponent` and the other timed grid components use.

## Notes
- `Stop("stopped")` (the `StopExtraction` default reason) deliberately suppresses the `ExtractionStopped` signal if extraction wasn't already running (`was || reason != "stopped"`) — every other stop reason (`"no_deposit"`, `"too_deep"`, `"depleted"`, etc.) always emits, even from an already-stopped state. This is a real, intentional asymmetry, not a bug: it's the difference between "user pressed stop on something already idle" (silent) and "the pump tried to run and hit a wall" (always reported).
- `DeliverYield`'s `Buffer` path and `RunCycle`'s buffer-capacity clamp both implement backpressure the same way `GridTransportChainComponent` and `GridHaulerComponent` do elsewhere in this batch: shut the pump in with the deposit intact rather than lose yield. The `IsStalled`/`ExtractionStalled`/`ExtractionResumed` signal pair mirrors `GridTransportChainComponent`'s `IsBlocked`/`ChainBlocked`/`ChainUnblocked` — same pattern, different names, not a duplicate (different files, different concerns).
- `GridSubsurfaceStoreComponent` is resolved via explicit path first, then a scene-wide `FindComponent` fallback — but `GridSubsurfaceStoreComponent` itself only exposes a `DataLayersPath` export with no fallback search (explicit-only, per its own doc comment). If a scene has the store node but never wires its own `DataLayersPath`, this extractor's fallback-resolved store will silently answer "no deposit" everywhere rather than surfacing a configuration warning of its own.
