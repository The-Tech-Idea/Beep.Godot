# GridObjectiveTrackerComponent

A `[Tool][GlobalClass]` `Node` and `ISaveable` implementer that owns the *runtime* state — activation, progress, and completion — for the objectives authored as `GridObjectiveDefinition` entries in its exported `Objectives` array. Per the class comment, it "Tracks objective activation, progress, completion, and save/load state for top-down and isometric builder games."

The core design decision, set up by `GridObjectiveDefinition`'s own doc comment, is the split between authored data (the `Resource`) and runtime state (this node's private `Dictionary<string, ObjectiveState>`). `ObjectiveState` is a private nested class with no `[Export]`s — it exists purely as internal bookkeeping keyed by normalized objective id, built lazily by `EnsureStates()` from whatever `GridObjectiveDefinition`s are currently in `Objectives`, so a definition added at runtime picks up default state (`Active = AutoActivateAll || definition.ActiveOnStart`) the next time any query method runs. Progress writes go through `SetProgress`, which is the single place that clamps to `[0, target]`, decides whether anything actually changed (to avoid redundant signal emission), and triggers auto-completion — every other mutator (`AddProgress`, `CompleteObjective`, `ResetObjective`) either calls into it or duplicates its completion logic deliberately (see Notes).

## Public API
- `[Signal] ObjectiveActivatedEventHandler(string objectiveId, bool active)` — emitted when `SetObjectiveActive` or `ResetObjective` changes activation.
- `[Signal] ObjectiveProgressChangedEventHandler(string objectiveId, int progress, int target)` — emitted whenever progress actually changes (including through auto-completion or `ResetObjective`).
- `[Signal] ObjectiveCompletedEventHandler(string objectiveId)` — emitted once, the first time an objective transitions to completed.
- `Godot.Collections.Array Objectives { get; set; } = new()` — the authored objective list; entries are read through `GridObjectiveDefinition.Enumerate`, so dictionaries and resources are both accepted.
- `bool ParticipatesInSave { get; set; } = true` — gates group membership (`SaveableHelper.Group`) and whether `Save`/`Load` write/read anything.
- `string SaveKey { get; set; } = "grid_world.objectives"` — key under `GameStateData.GameData` this component's state is stored at.
- `bool AutoActivateAll { get; set; } = false` — if true, every objective starts active regardless of its own `ActiveOnStart`.
- `bool SetObjectiveActive(string objectiveId, bool active)` — sets activation; returns `false` if the id has no state (unknown/unauthored objective); returns `true` without emitting a signal if the value didn't change.
- `bool AddProgress(string objectiveId, int amount = 1)` — adds `amount` to current progress via `SetProgress`; returns `false` if the objective has no state, isn't active, or is already completed (so progress cannot be added to a finished or inactive objective).
- `bool SetProgress(string objectiveId, int progress)` — clamps `progress` to `[0, EffectiveTargetCount]`, emits `ObjectiveProgressChanged` if the clamped value or completion state differs from current, and calls `CompleteObjective` if `AutoComplete` is set on the definition and the new progress reached target. Returns `false` if the objective/definition can't be resolved.
- `bool CompleteObjective(string objectiveId)` — forces progress to at least target and marks completed; idempotent (returns `true` without re-emitting `ObjectiveCompleted` if already completed).
- `bool ResetObjective(string objectiveId)` — zeroes progress, clears completion, and resets `Active` to `AutoActivateAll || definition.ActiveOnStart`; emits both progress-changed and activated signals.
- `bool IsComplete(string objectiveId)` / `bool IsActive(string objectiveId)` / `int GetProgress(string objectiveId)` / `int GetTarget(string objectiveId)` — read-only queries; each defaults safely (`false`/`false`/`0`/`1`) when the objective is unknown.
- `Godot.Collections.Array<string> GetActiveObjectives()` — ids of every currently-active objective, in `Objectives` array order.
- `Godot.Collections.Dictionary CaptureState()` — serializes every tracked `ObjectiveState` (id, progress, active, completed) into a dictionary under `"objectives"`.
- `void RestoreState(Godot.Collections.Dictionary state)` — restores progress/active/completed per objective id from a previously-captured dictionary; silently ignores entries for ids that have no current state (e.g. an objective removed from `Objectives` since the save was made).
- `void Save(GameBuilder.GameStateData state)` / `void Load(GameBuilder.GameStateData state)` — `ISaveable` implementation; writes/reads `CaptureState()`/`RestoreState()` under `SaveKey` in `state.GameData`, no-op if `SaveKey` is blank.
- `GridObjectiveDefinition? DefinitionFor(string objectiveId)` — looks up the authored definition by normalized id; linear scan over `Objectives` each call.

## Dependencies
- Uses `GridObjectiveDefinition.Enumerate`, `.Normalize`, `.NormalizedId()`, and `.EffectiveTargetCount` (this batch, `GridObjectiveDefinition.cs`) throughout — this is the tracker's only source of what objectives exist and what their targets/auto-complete flags are.
- Uses `GridVariantReader.TryDictionary`/`.Array` (outside this batch) to parse saved state dictionaries in `RestoreState`.
- Uses `SaveableHelper.Group` and implements `ISaveable` (both outside this batch) to participate in the addon's save system.
- Called into, within this batch: `GridObjectiveEventBinderComponent` resolves this component via `ObjectiveTrackerPath` (or scene search) and calls `AddProgress(id, amount)` as its sole write path — this is the batch's demonstrated production path for advancing objectives from gameplay events, versus tests or UI calling `SetProgress`/`CompleteObjective` directly.

## Notes
- `CompleteObjective` duplicates `SetProgress`'s completion logic (setting progress to target, emitting `ObjectiveProgressChanged`, emitting `ObjectiveCompleted`) rather than calling `SetProgress` internally — this means a direct `CompleteObjective` call always re-clamps progress to `Max(current, target)` and always re-emits `ObjectiveProgressChanged` even if progress was already at target, whereas `SetProgress` would have treated an unchanged value as a no-emit no-op. Not a bug, since the two entry points have different intent (force-complete vs. incremental), but it is a second place that knows how to transition an objective to completed.
- `AddProgress` refuses to act on an inactive objective (`!state.Active` short-circuits to `false`), but `SetProgress` and `CompleteObjective` do not check `Active` at all — so a caller using `SetProgress`/`CompleteObjective` directly (bypassing `AddProgress`) can progress or complete an objective that was never activated. This is consistent with `AddProgress` being the "normal gameplay" entry point (used by `GridObjectiveEventBinderComponent`) and the others being lower-level/administrative, but it is an asymmetry worth knowing if a caller expects `Active` to gate all mutation.
- `EnsureStates()` only *adds* missing states — it never removes a state whose definition was deleted from `Objectives` at runtime, so a removed objective's progress lingers in `_states` (and would still be exported by `CaptureState()`) until the component is destroyed. `RestoreState` correspondingly no-ops for ids with no current state, so a save made with an objective that's since been removed from the authored list is silently dropped on load rather than erroring.
