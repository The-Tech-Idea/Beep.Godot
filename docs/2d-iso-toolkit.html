Design Rules

  • Author visible Godot nodes at design time and attach behavior components to them.
  • Use exported NodePath fields to bind labels, buttons, panels, roots, and layers.
  • Use runtime generated controls only as an explicit fallback for prototypes or tests.
  • Use PainterlyTerrainComponent as the broad terrain base, connect it with GridPainterlyTerrainBridgeComponent, and keep TileMap layers only where cell detail or collision is needed.

Terrain And Projection

PainterlyTerrainComponent renders PainterlyTerrainSprite as a saturated plain biome base and renders PainterlyTerrainDetailSprite above it for overlays. Biome detail is off by default; when enabled, BiomeDetailCoverage, BiomeDetailPatchScale, and BiomeDetailPatchSoftness restrict it to seeded local patches instead of painting the whole scene. Desert/sand patches add dune ridges, dust, and pebbles; grass/forest patches add clumps and sparse flower flecks; earth/swamp adds damp patches; rock adds cracks and stone marks; snow/ice adds scratches and soft drifts. Bundled material textures are opt-in through UseBundledMaterialTextures; leave them off when the base should stay clean instead of noisy or pale.

RenderOffset positions the generated child Sprite2D when the painter component itself is authored as a plain Node. The default painter resolution now matches a 64px tile before the safety cap is applied, avoiding low-resolution upscale blur on normal maps. Use LastGenerationWasCapped, LastGeneratedPixelsPerTile, and LastAppliedTerrainScale to see when a large map was reduced by MaxGeneratedPixels.

GridTerrainGeneratorComponent writes seeded terrain kinds into GridCellDataComponent and reuses its noise samplers across the generation pass. GridPainterlyTerrainBridgeComponent then samples GridCellDataComponent and GridRoadComponent into the painterly base, passing terrain kind through so desert, grass, rock, snow, and swamp cells receive matching detail layers while flags, water effects, pathing, saves, and roads stay driven by the same grid state.

For one-owner startup, set TerrainGeneratorPath and GenerateBeforeFirstRebuild on the bridge, then leave the painter and generator GenerateOnReady flags disabled. The bridge generates cell data once, suppresses the duplicate change-triggered rebuild, and paints the shared state.

GridProjectionComponent is the shared world/cell conversion layer for both top-down and isometric scenes.

GridTileMapLayerBridgeComponent mirrors cell and road state into a Godot TileMapLayer when the scene needs tile collision or detail.

Selection, Tools, And Placement

GridSelectionComponent handles hover, click, and rectangle selection. GridInteractionModeComponent routes clicks across select, inspect, tool, build, and disabled modes.

GridInteractionModeBarComponent, GridInteractionStatusComponent, and GridInteractionCursorComponent expose mode, feedback, and valid/invalid cell outlines.

GridToolActionComponent can use CellDataPath and NavigationPath to reject direct clear, hoe, plant, or queue-job actions on water, lava, disallowed terrain, or out-of-bounds cells before mutating the grid.

GridPlacementComponent, GridBuildDefinition, GridBuildCatalogComponent, GridBuildToolbarComponent, and GridBuildSiteComponent cover build preview, resource cost, footprint reservation, terrain placement rules from GridCellDataComponent, navigation blocking through GridNavigationComponent, and build-site jobs.

Resources, Jobs, Crops, And Production

GridResourceWalletComponent stores primitive dictionary balances through StartingResourceAmounts. GridResourceAmount is used for build and recipe costs.

GridResourceBarComponent, GridResourceNodeComponent, and GridResourceScatterComponent expose HUD balances, gatherable objects, and seeded map resources. Resource nodes can reserve placement cells until depleted. Scatter can read GridCellDataComponent to avoid water, lava, blocked terrain, or non-allowed terrain kinds, and can reserve generated resource cells through placement occupancy.

GridJobQueueComponent, GridJobBoardComponent, GridJobEffectComponent, and GridSelectionJobCommandComponent turn selected cells into worker jobs. Selection job commands can read GridCellDataComponent and GridNavigationComponent to skip water, lava, and out-of-bounds cells before workers claim impossible jobs. Clear-land jobs can gather/deplete a resource node on the target cell and release its placement reservation.

GridCellDataComponent, GridCropDefinition, GridCropCatalogComponent, GridCalendarComponent, and GridCalendarHudComponent cover Stardew-style crops and dates.

GridProductionRecipe, GridProductionComponent, and GridProductionPanelComponent cover machine inputs, outputs, progress, pause, resume, and cancel.

Workers And State

GridNavigationComponent, GridRoadComponent, and GridPathFollowerComponent move workers through the cell world. Set CellDataPath on navigation and roads so they read blocked cell flags, impassable terrain kinds, and terrain movement costs from the same cell model that renders the map.

GridWorkerComponent, GridWorkerSpawnerComponent, GridWorkerSpawnerPanelComponent, and GridWorkerStatusPanelComponent provide the base-to-worker loop. Wire CellDataPath and PlacementPath on the spawner so base/depot spawns reject out-of-bounds cells, blocked cell flags, impassable terrain kinds, and occupied placement cells before creating a unit.

GridObjectComponent and GridObjectInspectorComponent make buildings, props, units, and resources selectable, including object kind/category and description text. Authored grid objects can reserve their placement and navigation footprint by wiring PlacementPath, NavigationPath, and ReserveFootprintOnReady. GridWorldStateComponent captures cells, roads, jobs, placement, navigation blocks, selection, and authored object state for saves, then reapplies object footprint reservations on restore.

HUD And UI Kit Practice

Use authored Control, Button, and Label nodes with KitPanelContainer, KitPushButton, KitLabel, KitLabelValue, KitToast, KitTooltip, and KitSpeechBubble. Bind component paths to those nodes instead of letting systems create hidden runtime panels.
