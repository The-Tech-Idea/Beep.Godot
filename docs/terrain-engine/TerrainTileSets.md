# TerrainTileSets

Support utility (shared world-data/model layer): the single place every terrain `TileSet` is assembled, its per-tile custom-data-layer contract defined, and its physics/navigation body shaped.

Before this file existed, every renderer built its own `TileSet` inline, which meant the custom data layer names (the contract a game reads to ask "what is this tile") were spelled out as string literals at up to five separate call sites — a silent way for one of them to drift from the others, since reading an undefined custom-data layer just returns nothing rather than erroring. `TerrainTileSets` centralizes that: it defines the named custom-data layers every terrain `TileSet` carries, derives what a tile's relief/water/passability *mean* from its terrain kind (rather than trusting a caller to pass those independently and possibly disagree with `TerrainLayers`), and builds the physics/navigation collision bodies per "ground" category (land/water/steep) so a game can choose per-agent whether water or cliffs block movement, using Godot's own layer/mask mechanism rather than the addon making that choice itself.

## Public API

- `static class Cell` — the custom-data-layer name contract: `const string Terrain = "terrain"`, `Resource = "resource"`, `Feature = "feature"`, `Relief = "relief"`, `IsWater = "is_water"`, `Passable = "passable"`.
- `static TileSet Create(Vector2I tileSize, bool isometric = false)` — builds a new `TileSet` of the given tile size (isometric diamond-down layout when `isometric` is true) and calls `DefineCellData` on it before returning.
- `static void DefineCellData(TileSet tileSet)` — idempotently adds any of the six named custom-data layers (see `Layers`) that `tileSet` doesn't already have, by name and `Variant.Type`; layers already present (e.g. on a hand-authored `TileSet`) are left untouched, so this is safe to call on developer-edited assets without disturbing their existing tile indices.
- `static void Describe(TileData? data, string terrainKind, string resource = "", string feature = "")` — writes the six custom-data values onto one `TileData`: `terrain`, `resource`, `feature` verbatim, and `relief`/`is_water`/`passable` *derived* from `terrainKind` via `TerrainLayers.LevelForKind`, `IsWaterKind`, and `kind != "rock"` respectively. No-ops silently if `data` is null.
- `static bool IsWaterKind(string terrainKind)` — true for exactly `"deep_water"`, `"shallow_water"`, `"water"`.
- `static bool IsLandKind(string terrainKind)` — true when `terrainKind` is non-empty and not a water kind (an empty string is explicitly neither land nor water — it means "no terrain assigned").
- `enum Ground { Land = 0, Water = 1, Steep = 2 }` — the three physics/navigation "what the ground IS" categories.
- `static void DefineBody(TileSet tileSet, uint[]? collisionLayers = null)` — ensures one physics layer and one navigation layer per `Ground` enum value exist on `tileSet` (added only if missing, so repeated calls are additive-safe), each physics layer given a distinct collision-layer bit (`1u << (i+1)` unless overridden by `collisionLayers`) and a collision **mask** of 0 (tiles collide with nothing; they are collided *with*).
- `static Ground GroundOf(string terrainKind)` — maps a terrain kind to its `Ground` category: water kinds → `Water`, `"rock"` → `Steep`, everything else → `Land`.
- `static void ShapeCell(TileData? data, string terrainKind, Vector2I cellSize)` — adds a square collision polygon and a matching square `NavigationPolygon` to `data`, both sized to `cellSize` and centred on the tile, on the physics/navigation layer index for `GroundOf(terrainKind)`. No-ops if `data` is null. Every cell gets both a collision shape and a navigation polygon on its own ground's layer (not one or the other) so a swimming or walking agent's own mask/navigation-layer choice — not this method — decides what blocks it.
- `static IReadOnlyList<string> Kinds` — the fixed, ordered list of every terrain kind the generator can produce (`"deep_water"`, `"shallow_water"`, `"grass"`, `"dry_grass"`, `"desert"`, `"sand"`, `"tundra"`, `"snow"`, `"ice"`, `"jungle"`, `"swamp"`, `"mud"`, `"gravel"`, `"rock"`); order is fixed deliberately so a kind's tile index stays stable across runs for a saved `TileSet`.
- `static Error Save(TileSet tileSet, string resPath)` — creates `resPath`'s parent directory if needed and saves `tileSet` there via `ResourceSaver.Save`, returning `Error.InvalidParameter` for a blank path and pushing a warning (but still returning the underlying `Error`) if the save itself fails.

## Dependencies

- `Describe` calls `TerrainLayers.LevelForKind(kind)` to derive the `relief` custom-data value — the single source of truth for which vertical band a terrain kind belongs to, shared with `TerrainTransitionLayerComponent`'s z-placement and `TerrainTileRendererComponent`'s layer ordering.
- Consumed by (not read by this file): `TerrainDataLayersComponent` (`Describe`, `ShapeCell`, `Create`, `DefineBody`, and every `Cell.*` constant for reading tile custom data back — `TerrainAt`, `ResourceAt`, `FeatureAt`, `ReliefAt`, `IsWaterAt`, `PassableAt`), `TerrainFieldBuilder` and `TerrainScaleConstraintStage` (`IsWaterKind`/`IsLandKind`), `TerrainFeatureStage` (`IsLandKind`), `TerrainGeneratorComponent` (`Kinds`, to enumerate every terrain kind e.g. for `TerrainKindsPresent()`), `TerrainIsometricRendererComponent` (`IsWaterKind`/`IsLandKind`), and `TerrainShaderSurface.BuildTileSet` (`Create`).
- Does not itself read `TerrainWorld`, `GeneratedTerrainField`, or any generation-stage output — it is a pure builder/classifier operating on whatever terrain-kind string and `TileData` it is handed.

## Notes

- `Save(TileSet, string)` has no callers anywhere in `addons/beep_game_builder_cs/` (confirmed by search) — it is accepted-but-unread: a fully implemented, documented public method for persisting a generated `TileSet` as a real editable asset, but nothing in the current codebase invokes it. Its doc comment describes a real, still-unmet need ("a developer can extend it with collision shapes... without that work being overwritten next time a map is generated"), so this reads as a planned integration point (e.g. an editor-dock "bake tileset" action) that was never wired up, not dead code to delete.
- `IsLandKind`'s empty-string handling ("the empty string is not land... writing that test by hand is how it came to be spelled twelve different ways") documents a past duplication defect across the engine that this method was written to resolve — worth knowing when auditing other terrain-kind checks for a fourteenth reimplementation.
- `DefineBody`'s per-ground collision-layer bit assignment (`1u << (i + 1)`) reserves bit 1 (`1u << 0`) implicitly for "Godot's default for everything" per the inline comment, but that reservation is never enforced or asserted anywhere in this file — it relies on `Ground`'s enum values starting at 0 and nothing else in the engine claiming bit 1 for a terrain-unrelated physics layer.
- No stale comments found; the file's comments consistently describe the code beneath them, including two comments that document past defects this exact code fixes (the twice-classified biome and the twelve-ways-spelled land check) rather than describing new code.
