# TerrainGeometry

Support utility: a stateless, `internal static` grid-algorithms class used by the generation stages, not itself a stage or a component.

`TerrainGeometry` holds the small set of array-based grid algorithms the terrain pipeline needs repeatedly — four-way neighbour enumeration, flood-fill connected-component labelling, multi-source BFS distance fields, percentile selection over a masked sample set, a majority vote, one per-cell hash and a few noise-shaping helpers. It is written for reuse of caller-supplied buffers rather than allocation, because (per its own doc comments) some of these operations run many times over a full field during one generation pass — the doc for `LabelComponents` says landmass bisection alone calls it "seventeen times over," and an earlier per-call-allocating version was the single largest cost in generation. `Neighbours4` says the same about its predecessor: a `yield` iterator allocated its state machine on every call, and at Huge the water and biome stages between them made two-thirds of a million of those per stage.

The other reason it exists is rule 3. Every helper here replaced two to five private copies that had already drifted: three different per-cell hashes (so one map's two isometric views disagreed about every cell's variant), several `Negate`/`CountTrue`/percentile-index copies, and five inline majority votes.

## Public API

- `static int Neighbours4(int index, int width, int height, Span<int> neighbours)` — writes the flat indices of the up-to-4 orthogonal neighbours of a cell into the caller's span, in the order −x, +x, −y, +y, and returns how many there are. Every breadth-first walk in the stages is order-sensitive, so this is the one order they all take; callers `stackalloc` a four-int span once, outside their loops.
- `static int LabelComponents(bool[] mask, int width, int height, int[] labels, int[] stack, List<int> sizes)` — flood-fills `mask` into 4-connected components with an iterative stack-based DFS (all buffers supplied by the caller, sized to the field, and reused): writes each true cell's component index into `labels` (−1 for a false cell), appends each component's cell count to `sizes`, and returns the component count. Each cell is labelled as it is pushed, so it enters the stack exactly once and a buffer the size of the field always fits.
- `static int CountComponents(bool[] mask, int width, int height, int[] labels, int[] stack)` — the count alone, over caller-supplied label and stack buffers of the mask's length. It allocates only the `List<int>` of sizes it then throws away.
- `static void DistanceTo(bool[] source, bool sourceValue, int width, int height, int[] distance, int[] queue)` — multi-source BFS writing each cell's step distance to the nearest cell where `source == sourceValue` (0 for those cells themselves) into `distance`. Taking the value to match rather than a mask means coast distance can be asked as "distance to where land is false" without building a negated copy. `queue` must hold the whole field; each cell is settled once, so it never overflows.
- `static int SortedSelection(float[] values, bool[] mask, float[] destination)` — copies the values where `mask` is true into `destination`, sorts that run ascending and returns its length, ready for `RankedValue`. This is how a Civ-style generator turns "20 % of land is hills" into a concrete cutoff regardless of how the noise happens to be distributed; the relief and feature stages each take two cutoffs from one selection, where each cutoff used to build and sort a list of its own.
- `static float RankedValue(IReadOnlyList<float> sorted, int count, float percentile)` — the value at a percentile of an already-sorted run (clamped 0–1, nearest-rank by rounding); 0 when `count` is 0.
- `static int CountTrue(bool[] values)` — how many cells a mask selects.
- `static TKey? MostCommon<TKey>(Dictionary<TKey, int> counts, TKey? fallback) where TKey : notnull` — the most-counted key, or `fallback` when nothing was counted. See below.
- `static float Normalized(float signedNoise)` — remaps `[-1, 1]` to `[0, 1]`.
- `static float Smooth(float value)` — smoothstep-style cubic ease (`3v² − 2v³`).
- `static float Ridged(float signedNoise)` — `1 − |signedNoise|`, turning smooth fbm into sharp crests so mountain ranges read as ranges instead of round blobs.
- `static float Hash01(int x, int y, int seed)` — deterministic per-cell hash in `[0, 1)`: one seed plus a cell decides the same value every time, which is what lets jitter and selection be reproduced from a seed instead of stored. It was copy-pasted byte-for-byte into eight files before being pulled here — two of the eight even with the seed and cell arguments in a different order, which is itself the evidence they were pasted rather than shared.
- `static int HashInt(int x, int y, int seed)` — the same mix kept as a raw int, for callers that index by modulo rather than by a unit float.
- `const int VariantSalt` — the salt for per-cell *variant* choice (which of a terrain's interchangeable frames a cell shows). One value, so the isometric block view and the autotile view pick the same variant for the same cell; they used two different hashes before and disagreed. The number is the FNV offset basis the block view had hard-coded, kept so the consolidation moved where the mix lives and not what it draws.

### `MostCommon` is generic, and that is the point (FEAT-10)

It began as `MostCommon(Dictionary<string,int>, string)` — a vote over terrain-kind names, replacing five inline copies (tile reduction, the two landmass votes in the scale constraint, the coherence stage's two, the shoreline's re-vote). FEAT-10 made it `MostCommon<TKey>(Dictionary<TKey,int>, TKey?)` because [`GridMinimapComponent`](../grid-system/GridMinimapComponent.md) needed the *same* majority vote over start-area **indices** that it already ran over terrain kinds, in the same downsampled block. A second vote written beside it would have meant a block picking its terrain by one rule and its owner by another — visibly, at any downsample above 1:1, as a tint that does not line up with the ground it tints.

- **Ties go to the first key counted**, because every one of the five inline votes it replaced already compared with a strict greater-than over the same insertion-ordered dictionary. Same input, same winner — which is why the change was a consolidation and not a behaviour change.
- **Existing call sites are unchanged**: `TKey` infers to `string` from the argument, so the terrain-kind votes read exactly as before.
- `[return: NotNullIfNotNull(nameof(fallback))]` says a non-null fallback guarantees a non-null result, so `MostCommon(counts, "")` is a non-null `string` and `MostCommon(areas, 0)` is a plain `int` — a caller never has to invent a "nothing was counted" answer, because it supplied one.
- The nullability is on the fallback, not the dictionary: an empty `counts` returns the fallback rather than throwing, which is what makes it safe to call per texel over blocks that may be entirely outside the map.

## Dependencies

- Depends on nothing but `System` and Godot's `Mathf`: it operates purely on caller-supplied `bool[]`/`float[]`/`Span<int>`/`Dictionary<,>` buffers. No node, no `[Export]`, no state.
- Called by the generation stages under `ecs/terrain` — the source comments name tile reduction, the scale constraint's two landmass votes, the coherence stage's two and the shoreline's re-vote as the five sites `MostCommon` replaced, and the isometric block view, the autotile alternative picker and the resource scatter's amount roll as the private hashes `Hash01`/`HashInt` replaced.
- Called, since FEAT-10, by `ecs/grid/ui/GridMinimapComponent.cs`: its `BlockColour` calls `MostCommon` twice per baked texel, once over terrain kinds and once over start-area ids. `internal` is no obstacle there — the whole addon is one assembly.

## Notes

- Purely a support/algorithms module — no state, no Godot node, nothing game-facing. It is the one file in the terrain folder with no coupling to the pipeline's data model, which is exactly why a grid-side view can share it without dragging the generator in behind it.
- `tests/addon_contract_scan.ps1` pins both halves of the one-owner rule. It requires `TerrainGeometry` to declare `public const int VariantSalt`, `public static int CountTrue(`, `public static float RankedValue(` and `public static TKey? MostCommon<TKey>(` — the last was updated to the generic signature when FEAT-10 landed — and it then sweeps every `.cs` file under `ecs/terrain` **and** `ecs/grid` for a private copy of one of those helpers or for any of the five hash constants. **Its blind spot:** the sweep bans `private static string MostCommon(`, the *string-typed* copy. A file that regrew a generic private copy would not trip it.
- `LabelComponents` and `DistanceTo` each declare a local function (`Push`, `Visit`) inside their loop rather than walking neighbours through an iterator or a delegate — the same allocation-conscious choice `Neighbours4` was written for.
- `CountComponents` takes the caller's buffers now; it is not the "fresh allocation on a cold path" convenience it once was. Only the `List<int>` of component sizes is allocated per call.
- `MostCommon`, `CountTrue`, `RankedValue` and the hashes are the four helpers whose duplication history is written into the source comments. Read those before adding a fifth private copy of anything here.
