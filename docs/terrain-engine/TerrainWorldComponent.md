# TerrainWorldComponent

Game-facing component — "THE map/world creation component": the single node a scene drops in to generate a world (via a `TerrainGeneratorComponent`) and draw it (via the renderer components handled in its `.Drawing.cs` partial). It is also the world's `ISaveable`: it persists the **recipe** (the axes and the seed) and regenerates the same world from it on load.

Per its header comment, this replaces logic that used to live welded into the lab's scene controller; every demo re-implemented the same three steps (generate, rebuild renderers, report) as its own hundred-line controller, and the copies drifted (one reported continents, another landmasses; one framed the camera by scaling the world, another by moving a camera). This component owns none of what the generation axes *mean* (that's `TerrainMapSetup`) or how they reach the generator (`TerrainGeneratorComponent.ApplyMapSetup`) — it only carries the scene's choice of axes and renderers and drives the two doors, `NewWorld()` and `RestoreWorld()`.

**The recipe is the save; the cells are the map.** The generated world — relief, elevation, resources, start positions, the kind every cell began as — is a pure function of the axes and seed, so that is what gets saved: nine small values, not eight layers of derivable tiles and not the generator's forty-field settings record (which `ConfigureGenerator` overwrites from the axes anyway). On load the world is regenerated and drawn, and **nothing is written into the grid's cells**: the live map is `GridCellDataComponent`'s, saved by `GridWorldStateComponent` with every edit the player made, and a regenerated world must not paint over it. That is the split OpenTTD and Widelands keep — one saved tile array, and generation is what fills it the first time. Before this the seed was never saved at all: a reload drew the scene's authored `Seed` over cells restored from a different world.

## Public API

- Background painted builds report `Preparing painted terrain` while copying live
  visual samples at `PublicationCellsPerFrame`. They retain the previous rendered
  surface until that copy is complete, then draw and prepare collision. Changed
  sources abort publication without installing a partial snapshot. This occurs
  after live-cell commit and does not provide rollback. `Computing painted coast`
  then reports detached coast/lake pixel computation; contour reconstruction and
  texture upload are still synchronous.

- `BeginNewWorld()` starts background generation. `IsGenerating` stays true through
  staged gameplay-cell preparation and budgeted native collision publication.
- `CanCancelGeneration` is true before live cells are committed. `CancelGeneration()`
  preserves the old world before that boundary; after commit it leaves publication
  running. Disable Cancel while this property is false.
- With `CollisionPath` assigned, background completion waits for all queued chunks
  and a native physics frame. `WorldBuilt` is not emitted for rejected collision
  geometry or a removed/invalid consumer; `GenerationFinished(false, message)` reports
  failure. Renderer/collision failures after commit do not roll back terrain.
- `GenerationProgress` reports `Preparing terrain collision` during this final phase.
  `BuiltSize` and saved recipe already describe the committed field, but gameplay
  should wait for successful completion. Synchronous `NewWorld`, `RestoreWorld` and
  `Redraw` retain their immediate collision rebuilds.

- `UseCustomBounds` / `CustomBounds`: opt into exact positive cell dimensions instead of a named map-size preset.
- `UseCustomLandCoverage` / `LandCoverage`: override the shape/sea-level land footprint with a finite value from 0.05 to 0.92, before inland lakes and rivers. This is not final dry-cell coverage. Invalid enabled overrides cancel generation without replacing live cells.
- `UseCustomClimateSpan` / `ClimateLatitudeSpan`: specify a geographic latitude range independent of grid resolution. Zero means a single latitude, one means planetary climate. Temperature still sets the latitude centre; altitude cooling and moisture remain active. Biome region-size rules stay enabled. Oilfield Days uses its regional kilometres divided by 10000 as a geographic scale convention, rather than treating 240 gameplay tiles as a planet.
- The recipe (version 4 since FEAT-09; version 3 added these) persists bounds, land-coverage and climate-span switches and values. Restore regenerates recipe data without overwriting live edits; disabling an override returns to the corresponding automatic rule.
- `int StartAreaRadius` `[Export]` (0–32, default 0) — radius, in cells, of the area reserved around every player start (FEAT-09). `ConfigureGenerator` pushes it onto the generator clamped to 0–32, so the generator's own Inspector radius is discarded for a world built here. Recipe version 4 saves it as `start_area_radius`; `RestoreState` reads a missing key as 0, because worlds saved before version 4 had no start areas. The generator's `StartKit` is not part of the recipe and `ConfigureGenerator` does not touch it, the same limitation as the `Resources` catalogue.
- `[Signal] WorldBuiltEventHandler WorldBuilt(Vector2I size)` — emitted after a world is generated and drawn, by both `NewWorld()` and `RestoreWorld()`; a camera framing the map cares that there is a world, not which door it came through.
- `NodePath GeneratorPath` `[Export]` — the `TerrainGeneratorComponent` both doors drive.
- `NodePath PaintedRendererPath`, `TileRendererPath`, `IsometricRendererPath`, `IsometricAutotileRendererPath`, `FeaturesPath`, `IsometricFeaturesPath`, `MapOverlayPath`, `ReliefRendererPath`, `ResourceRendererPath`, `DataLayersPath` `[Export]` — optional paths to each renderer/data layer; an unset one is simply skipped by `Draw()`, not treated as an error.
- `NodePath SpawnsPath` `[Export]` (FEAT-12, optional) — a `Spawns` node (a `Node2D`, conventionally under the map root) this world writes one `Start_<k>` `Marker2D` into per player start, through `TerrainSpawnMarkers.Emit`. Markers are ordinary scene nodes, so a map saved as a `.tscn` keeps its starts with no generator present, which is what [the TileMapLayer output contract](../game-builder/TILEMAP_OUTPUT.md#spawns-implemented-feat-09feat-12) requires of a published map; `GridStartAreaComponent.SpawnsRootPath` reads them back. Left empty, nothing is written and nothing is cleared. The emission itself lives in the Drawing.cs partial (`EmitSpawnMarkers`).
- `TerrainShape MapType`, `TerrainMapSize MapSize`, `TerrainWorldAge WorldAge`, `TerrainTemperature Temperature`, `TerrainRainfall Rainfall`, `TerrainSeaLevel SeaLevel`, `TerrainResourceLevel ResourceLevel`, `ResourceSet Resources`, `int Seed` (default `31415`) `[Export]` — the world's generation axes: the recipe. Forwarded to the generator verbatim by `ConfigureGenerator`, and the whole of what `CaptureState()` saves.
- `TerrainProjection Projection` `[Export]` (default `Painted`) — which renderer set `Draw()` shows/rebuilds. A view preference, not part of the recipe; not saved here.
- `TerrainWaterLook? WaterLook` `[Export]` (VIEW-04, optional) — how this world's sea looks, in every view that draws one. `Draw()` pushes it to the painted, tile, block-isometric and isometric-autotile renderers exactly as it pushes `PropSizing`, so switching view cannot change the ocean. Left unassigned, every renderer falls back to `TerrainWaterLook.Shared` — the shipped defaults, which is still **one** sea rather than one per renderer. Render configuration, not recipe: not saved and not restored. The four shipped terrain scenes assign `textures/terrain/terrain_water_look.tres`. See [TerrainWaterLook](TerrainWaterLook.md).
- `TerrainMapArt? MapArt`, `TerrainPropSizing? PropSizing` `[Export]` — the other two look resources `Draw()` pushes onto the renderers; `MapArt` reaches the painted view always and the flat companions only under `Painted`.
- `bool BuildOnReady` `[Export]` (default `true`) — when true and not running in the editor, `_Ready()` defers `NewWorldOnReady()`, which calls `NewWorld()` unless a save has already restored the recipe by the time it runs (see `_restoredFromSave` below).
- `bool ParticipatesInSave` `[Export]` (default `true`) — whether this world joins `SaveableHelper.Group` in `_Ready()`. Off for a lab or a map viewer with no game state to belong to.
- `string SaveKey` `[Export]` (default `"terrain_world.recipe"`) — the `GameData` key the recipe is written under.
- `Callable GenerateMap` `[ExportToolButton("Generate map")]` — editor-only button wrapping `Callable.From(NewWorld)`; per its doc comment this is deliberately the *only* way a map gets (re)built in the editor — `BuildOnReady` is intentionally not honoured there, so opening a scene never silently overwrites a hand-authored map.
- `Vector2I BuiltSize { get; private set; }` — size (tiles) of the last world either door produced; used by `PreviewExtent()` (Drawing.cs) as a fallback before any build has run, and saved as a sanity check.
- `_Ready()` — outside the editor: joins the saveables group when `ParticipatesInSave`, and defers `NewWorldOnReady()` when `BuildOnReady`.
- `_ExitTree()` — leaves the saveables group.
- `_GetConfigurationWarnings()` — warns when `GeneratorPath` is empty, or when `ParticipatesInSave` is on with an empty `SaveKey`; none of the ten renderer/data-layer paths are checked, nor `SpawnsPath` (which reports at draw time instead: a `SpawnsPath` that is not a `Node2D` pushes a warning and writes no markers).
- `void NewWorld()` — the **new-world door**: `ConfigureGenerator`, then `_generator.GenerateTerrain()` (which fills the wired `GridCellDataComponent`), then `Draw(size)`, then `WorldBuilt`. What the lab's Generate button, the editor tool button and `BuildOnReady` call.
- `void RestoreWorld()` — the **saved-world door**: `ConfigureGenerator`, then `_generator.ResolveField()` — the regeneration, deliberately *not* `GenerateTerrain` — then `Draw(size)` (which rebuilds the data layers and every renderer), then `WorldBuilt`. Writes nothing into the cells. Order-free with respect to the other saveables: the world, `GridWorldStateComponent` and `GridSubsurfaceStoreComponent` write disjoint stores, and the store reads the regenerated layers lazily, never inside its `Load`.
- `Godot.Collections.Dictionary CaptureState()` — the recipe: `version` (4), the eight axes as ints (`map_type`, `map_size`, `world_age`, `temperature`, `rainfall`, `sea_level`, `resource_level`, `resources`), the exact-recipe switches and values, `seed`, `start_area_radius`, and `built_size`.
- `void RestoreState(Godot.Collections.Dictionary state)` — reads the recipe into the axes (each falling back to its current value when a key is missing; `start_area_radius` falls back to 0), sets `_restoredFromSave`, calls `RestoreWorld()`, then warns if the saved `built_size` and the reproduced `BuiltSize` disagree — the one thing worth checking after a regeneration, since it means the meaning of a size step changed since the save and the restored cells no longer share an extent with the world drawn under them.
- `void Save(GameStateData)` / `void Load(GameStateData)` — ordinary public `ISaveable` implementation writing/reading `CaptureState()`/`RestoreState()` under `SaveKey`, the same shape as `GridWorldStateComponent` and `GridSubsurfaceStoreComponent`.
- `Godot.Collections.Dictionary Diagnostics()` — resolves and returns `_generator.GetGenerationDiagnostics()`, or an empty `Dictionary` if there is no generator.
- `string StatusLine()` — returns `""` if there's no generator; otherwise formats one line (built size, landform name, land/ocean/lake coverage, river coverage, landmass count vs. requested, resource count, start count, generation time) sourced entirely from `_generator.GetGenerationDiagnostics()` and `_generator.Landform`. When the diagnostics' `start_area_count` is above 0 it appends `  |  areas U of N usable` (U = `start_area_usable_count`, N = `start_area_count`).
- `ConfigureGenerator(out Vector2I size)` *(private)* — the step both doors share, so a new world and a restored one are configured identically: resolves nodes, warns and returns false if there's no generator, computes `size` from `TerrainMapSetup.BoundsFor(MapSize)`, stores it as `BuiltSize`, pushes `BoundsSize`/`Seed`/`ApplyMapSetup(...)`/`ResourceSet`/`StartAreaRadius` onto the generator and forces `UseClimateBiomeMaps`/`UseScaleRules` on. Its doc comment names the overwritten settings, `StartAreaRadius` included; `tests/addon_contract_scan.ps1` keeps the two in step.
- `NewWorldOnReady()` *(private)* — the deferred `BuildOnReady` target; returns without building when `_restoredFromSave` is set.
- `LandformName(TerrainGeneratorComponent.LandformMode)` *(private, static)* — maps `Island`/`Archipelago`/anything else to `"island"`/`"archipelago"`/`"mainland"`.
- `Resolve()` *(private)* — resolves every renderer/generator field from its NodePath through `Refresh<T>`, which re-resolves any cached reference that is no longer a valid instance.

## Dependencies

- Drives `TerrainGeneratorComponent` — `BoundsSize`, `Seed`, `ApplyMapSetup(...)`, `ResourceSet`, `StartAreaRadius`, `UseClimateBiomeMaps`, `UseScaleRules`, `GenerateTerrain()` (new world only), `ResolveField()` (restore, and again for the start reports the spawn markers are written from), `GetGenerationDiagnostics()`, `GetStartPositions()` (used from the Drawing.cs partial), `BoundsOrigin`, `Landform`/`LandformMode` — all defined in `TerrainGeneratorComponent.cs`.
- Calls `TerrainSpawnMarkers.Emit` (`TerrainSpawnMarkers.cs`) from the Drawing.cs partial when `SpawnsPath` is set.
- Reads `TerrainMapSetup.BoundsFor(MapSize)` from `TerrainMapSetup.cs`, which is also where `TerrainShape`, `TerrainMapSize`, `TerrainWorldAge`, `TerrainTemperature`, `TerrainRainfall`, `TerrainSeaLevel`, `TerrainResourceLevel` are declared.
- `ResourceSet` (the `Resources` export's type) is declared in `TerrainResourceStage.cs`.
- Parses the saved recipe through `GridVariantReader.Int`/`.Vector2I`/`.TryDictionary` (`ecs/grid/GridVariantReader.cs`), the same tolerant reader every grid saveable uses.
- Resolves node references that `TerrainWorldComponent.Drawing.cs` then reads/writes: `TerrainPaintedRendererComponent`, `TerrainTileRendererComponent`, `TerrainIsometricRendererComponent`, `TerrainIsometricAutotileRendererComponent`, `TerrainFeatureRendererComponent`, `TerrainIsometricFeatureRendererComponent`, `TerrainMapOverlayComponent`, `TerrainReliefRendererComponent`, `TerrainResourceRendererComponent`, `TerrainDataLayersComponent`.
- Is itself read by `TerrainWorldCameraComponent.cs` (`PreviewExtent`/`StartPositionView`/`WorldBuilt`), `TerrainWorldStatusComponent.cs` (`StatusLine`/`WorldBuilt`) and `TerrainLabComponent.cs` (`NewWorld`).
- Split across two files: this file plus `TerrainWorldComponent.Drawing.cs` (the `Draw`/`StartPositionView`/`PreviewExtent` partial).

## Notes

- `_GetConfigurationWarnings()` checks only `GeneratorPath` and the save key; none of the ten renderer/data-layer `NodePath`s are validated. This matches the documented "each renderer is optional" design for the *drawing* projections, but it also means a scene that forgot to wire `DataLayersPath` gets no editor warning even though `Draw()` rebuilds the data layers unconditionally for gameplay cell queries to work.
- `BuildOnReady`'s "skipped in the editor" behaviour is both documented and implemented (`_Ready()` returns early on `Engine.IsEditorHint()`), and its "yields to a save" behaviour is guarded the same way `tests/terrain_world_recipe_probe.gd` exercises it: a world added with `BuildOnReady` and restored in the same frame keeps the restored cells through the ready frame, while an explicit `NewWorld()` afterwards still builds a fresh world — the yield is for the deferred build only.
- `StatusLine()`'s doc comment cites the historical "one demo reported continents, another landmasses" bug as its motivation, and the code genuinely centralises the fix (a single `string.Format` sourced only from generator diagnostics) — comment matches current behaviour.
- Guards: `tests/addon_contract_scan.ps1` pins `ISaveable`, the save key, both doors, `CaptureState`/`RestoreState`, the `seed` entry, the `_restoredFromSave` yield, that `RestoreWorld` calls `ResolveField()` and never `GenerateTerrain()`, that both doors go through `ConfigureGenerator`, and that no `Build()` returns. `tests/terrain_world_recipe_probe.gd` round-trips the recipe against an edited cell and a worked deposit. It also checks that `StartAreaRadius` reaches the generator, that `start_area_radius` is saved at recipe version 4, the `areas U of N usable` status suffix, that nothing is reserved at radius 0, and that a restore brings back the same reserved cells.
