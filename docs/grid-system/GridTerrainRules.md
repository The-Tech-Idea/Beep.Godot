# GridTerrainRules

The one place the grid components agree on what a terrain-kind string means for building and working. It is a small `internal static class` — not a component, has no Godot node identity, `[Tool]`, or `[GlobalClass]` attribute — of pure helper functions: a default blocked-kinds list, a string normalizer, and two membership checks.

It exists to undo a specific, named drift: the doc comment states that seven components used to each carry their own copy of the blocked-kinds default list, their own `Normalize`, and their own allowed/blocked check loops, and the copies had already diverged — one normalizer forgot the space-and-dash replacement, and none of the default lists agreed with `TerrainTileSets.IsWaterKind` about shallow water until that was fixed by hand in six files at once. This is the same kind of consolidation `Hash01` received on the terrain side (outside this batch), done for the identical reason: rule 3 territory — one owner per fact, not seven copies drifting independently. `GridNavigationComponent` (outside this batch) is called out by name as a deliberate, documented exception: it keeps its *own* blocked default without `shallow_water`, because units should wade through shallow water at a cost while nothing may be *built* there — a genuine behavioral difference, not an unmigrated straggler.

## Public API
- `static Godot.Collections.Array<string> DefaultBlockedTerrainKinds()` — returns `{"water", "sea", "ocean", "deep_water", "shallow_water", "lava"}` as a **fresh array on every call**, because exported Godot arrays must not share one instance across components (an `[Export]` default expression that returned a cached static array would let one component's edits in the inspector leak into every other component using the same default).
- `static string Normalize(string value)` — trims, lowercases (invariant), and replaces both spaces and dashes with underscores; empty/whitespace input normalizes to `""`.
- `static bool MatchesAny(string normalizedKind, Godot.Collections.Array<string> kinds)` — true if `normalizedKind` (already expected to be normalized by the caller) equals `Normalize(kind)` for any entry in `kinds`. Always false for an empty `normalizedKind`.
- `static bool IsAllowed(string normalizedKind, Godot.Collections.Array<string> allowed)` — an empty `allowed` list allows everything; otherwise membership (`MatchesAny`) decides.

## Dependencies
- Calls nothing outside itself — no `NodePath`, no Godot node lifecycle, no signals. Pure static helpers.
- Not established from this batch alone which of the seven components the doc comment references as former duplicate-holders now call into `GridTerrainRules` — none of the other eight files in this batch (`GridExtractionManagerComponent`, `GridExtractorComponent`, `GridHaulerComponent`, `GridTransportChainComponent`, `GridTransportManagerComponent`, `GridStorageComponent`, `GridSubsurfaceStoreComponent`, `GridProspectingComponent`) reference `GridTerrainRules`, `DefaultBlockedTerrainKinds`, `MatchesAny`, or `IsAllowed` — the consumers are building/placement/pathing/scattering components outside this logistics batch (matching the doc comment's own examples: "nothing should be built, roaded, spawned, or scattered on").

## Notes
- `internal`, not `public` — deliberately not part of the addon's external API surface; it is infrastructure for the grid components' own internal agreement, not something a game script is expected to call directly (a GDScript extractor participating via duck typing, for instance, has no need of it).
- `GridProspectingComponent` (this batch) has its own private `NormalizeKind` for job-kind strings that lowercases and replaces spaces with underscores but — unlike `GridTerrainRules.Normalize` — does *not* also replace dashes; see `GridProspectingComponent.md` Notes for the comparison. It normalizes a different kind of string (job kind, not terrain kind) so it is not obviously the duplicate this file was written to eliminate, but it is the same shape of divergence risk this file's own doc comment warns about.
- No accepted-but-unread settings, no dead code, no silent failure path: every function is a small, total, side-effect-free transform over its inputs.
