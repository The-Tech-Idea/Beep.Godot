# FIX-07 — Requeue-on-load drops world execution: an in-progress world-owned job is silently lost across save/load

**Type:** fix · **Area:** `GridJobExecutionComponent`, `GridWorkerDispatchComponent`, `GridJobQueueComponent`, `GridWorkerComponent` · **Status:** **PROPOSED 2026-09-11** · **Effort:** M (1–2 days) · **Risk:** medium

## Finding

The job queue's `RequeueClaimedJobsOnLoad` defaults `true` (`GridJobQueueComponent.cs:53`) and, on load, converts **every** saved `Claimed` job to `Queued` and clears its `ClaimedBy` (`GridJobQueueComponent.cs:545-549`, inside `LoadJobs`). That default serves exactly one of the two restore models the queue backs, and silently breaks the other.

1. **The requeue is a blunt override of the principled conflict resolution that already runs.** `LoadJobs` ends with `RebuildReservations()` (`GridJobQueueComponent.cs:556` → `GridJobQueueComponent.Reservations.cs:64-90`), which already re-derives every claim from the saved `State`/`ClaimedBy`/`ReservedCell` and requeues **only** genuinely conflicting claims (duplicate worker id, duplicate/occupied reserved cell, invalid cell — lines 76-82). A saved world-execution claim carries a stable worker id and a valid reserved cell, so `RebuildReservations` would restore it intact — the blind flip at 545-549 destroys it *before* the conflict logic ever sees it.

2. **World-execution restore only succeeds while the claim is still `Claimed`.** `GridJobExecutionComponent.CanExecute` requires `GetJobState == Claimed` **and** `GetJobClaimedBy == worker` **and** `GetReservedWorkCell == entry.Cell` (`GridJobExecutionComponent.cs:82-83`); `GridJobQueueComponent.CanBindExecutor` independently requires `job.State == Claimed && job.ClaimedBy == workerId` (`GridJobQueueComponent.Execution.cs:28-32`). A requeued job (`Queued`, empty `ClaimedBy`) fails all of these. `RestoreState` is all-or-nothing: the first entry that fails `CanExecute`/`CanBindExecutor` returns `false` at `GridJobExecutionComponent.cs:180` — before `EmitSignal(ExecutionStateRestored)` at `:190` — and `Load` at `:197` discards that `bool`, so the whole execution restore is dropped with no signal and no warning.

3. **The worker then parks Idle and the progress is gone.** A world-owned worker's `Load` short-circuits to `SynchronizeExecution()` and returns without re-claiming (`GridWorkerComponent.cs:236-241`). With the execution empty, `SynchronizeExecution` reads an empty `GetWorkerJob`, sets `_worldOwned = false`, clears `CurrentJobId`, and calls `SetState(WorkerState.Idle)` (`GridWorkerComponent.Execution.cs:42-50`). The dispatch path fails the same way: `GridWorkerDispatchComponent.RestoreState`'s `AssignmentMatches` requires `Claimed` (`GridWorkerDispatchComponent.Persistence.cs:89-93`), so a requeued assignment returns `false` at line 68-69, and `Load` again ignores the discarded `bool` (`:96-98`) — despite the method's own doc promising to restore "queue (retaining claims)" (`:33`). Net: a worker that was actively building/gathering at save time comes back Idle, its job back in the open queue, its remaining-turns progress dropped.

4. **The asymmetry is explicit in the code, and the default was reasoned only for the other model.** The **actor** (non-world) restore branch *does* tolerate a requeued job: it re-claims it under the saved worker id — `if (GetJobState == Queued) ClaimJob(CurrentJobId, WorkerId)` then `TryReserveWorkCell(...)` (`GridWorkerComponent.cs:249-252`). The world-execution and dispatch branches have no equivalent. The default's justification is written only for the actor case: `GridPlacementSmoke.cs:4683-4685` comments that a claim "never survives a load — worker ids embed instance ids no reload reproduces, so a loaded claimed job would belong to a ghost forever," and the two tests that touch the flag (`:4656` sets it `false` to assert parse fidelity, `:4686` asserts the default requeues a `ghost_worker_123` claim) never exercise a world executor. So the world-execution regression is entirely uncaught.

Restore ordering compounds it: `GameStateManagerComponent.RestoreAllSaveables` loads non-actor saveables in tree order, then `ActorRegistryComponent` last (`GameStateManagerComponent.cs:445-450`); the queue-before-executor order that execution restore already depends on is not pinned, only conventional.

## Design

The queue is the sole owner of the claim fact and must stay so; the fix is to make the world-execution and dispatch restore paths **re-assert their saved claim through the queue's public API**, exactly as the actor path already does at `GridWorkerComponent.cs:249-252` — not to teach the queue about executors.

- **`GridJobExecutionComponent.RestoreState`:** before the `CanExecute`/`CanBindExecutor` gate, for each saved `Execution` entry whose job the queue reports `Queued` (i.e. it was requeued on load), re-claim it under the saved worker and restore its cell: `_queue.ClaimJob(entry.Job, entry.Worker)` then `_queue.TryReserveWorkCell(entry.Job, entry.Worker, entry.Cell)`. `ClaimJob` (`GridJobQueueComponent.cs:308-317`) succeeds because after requeue the job is `Queued`, the worker is claimable, and the approach cell is free; `TryReserveWorkCell` (`GridJobQueueComponent.Reservations.cs:27-41`) then moves the reservation to the saved work cell so `CanExecute`'s `GetReservedWorkCell == entry.Cell` check passes. If either call fails, fall through to the existing gate (the entry is genuinely un-restorable and the current all-or-nothing behaviour stands). This is the same three-line pattern the actor branch uses — the queue stays the one claim owner; the executor merely re-states the claim it recorded.
- **`GridWorkerDispatchComponent.RestoreState`:** mirror the same re-claim for a restored `Worker` whose `Job` the queue reports `Queued`, before `AssignmentMatches`/`CanBindDispatcher` (`GridWorkerDispatchComponent.Persistence.cs:68-69,89-93`): re-claim under `id`, then reserve the route/work cell it validates against.
- **This leaves the actor ghost-worker guarantee intact.** A claim by a worker id no reload reproduces is bound by no executor and no dispatcher and re-claimed by no live actor (the new-id actor fails `GetJobClaimedBy == WorkerId` at `GridWorkerComponent.cs:251` and releases it), so it stays `Queued` — precisely what `RequeueClaimedJobsOnLoad` was reasoned for (`GridPlacementSmoke.cs:4683-4685`). The flag therefore keeps doing its one legitimate job; only the world/dispatch paths gain the re-claim that makes them symmetric with the actor path.
- **Do not add a warning-only guard as the fix.** The finding's fallback option ("at minimum warn when a scene wires `GridJobExecutionComponent` with the flag still true") is not a fix — it documents the defect and ships it. Once the re-claim lands, the flag and a world executor coexist correctly and no warning is warranted.
- **Whether to remove the flag is the owner's call, not the implementer's.** `RequeueClaimedJobsOnLoad` is a public `[Export]` on a `[GlobalClass]` with real consumers (the two smoke tests, and scene authors). The re-claim makes the flag harmless-when-true rather than redundant, so this change does **not** remove it; if Fahad wants the flag retired in favour of letting `RebuildReservations` own all conflict resolution, that is a separate decision.
- **Alternative considered — a post-restore reconciliation phase** (queue keeps claims `Claimed` on load; a third `GameStateManagerComponent` phase, after actors load, requeues only claims bound to no executor/dispatcher and held by no live actor, reading the now-populated `_executionOwners`/`_dispatchOwners`). It is the more principled "one owner for *is this claim orphaned*", but it edits the shared restore orchestrator (`GameStateManagerComponent.cs:445-453`) and adds a phase — larger surface and a heavier collision risk for a bug the localized re-claim already closes. Recorded, not chosen.

## Guards (fail first)

A behavioural smoke in `tests/GridPlacementSmoke.cs` (its harness already builds queue + registry + clock + grid and manipulates `RequeueClaimedJobsOnLoad`, e.g. around `:4656`):

- **Assertion:** build a world-owned worker actively executing a job — queue with a job `Claimed` by `worker_1`, a bound `GridJobExecutionComponent`, work partially advanced — and `CaptureState` all three components. Into a fresh queue/execution/worker set (queue node ordered before the executor), `LoadJobs`/`RestoreState`/`Load` with the **default** `RequeueClaimedJobsOnLoad = true`. Assert after load: `GetJobState(job) == Claimed`, `GetJobClaimedBy(job) == "worker_1"`, `GetReservedWorkCell(job) == savedCell`, the executor reports `GetWorkerJob("worker_1") == job`, `GetJobRemainingTurns(job)` equals the saved remaining, and the worker state is `Working` (not `Idle`).
- **Mutation that trips it:** revert the `GridJobExecutionComponent.RestoreState` re-claim (delete the `ClaimJob`/`TryReserveWorkCell` lines). The requeued job then fails `CanExecute`/`CanBindExecutor`, `RestoreState` returns `false` at `GridJobExecutionComponent.cs:180`, `SynchronizeExecution` parks the worker Idle — the state/owner/remaining assertions fail. (Confirm it *can* fail by running the assertion against unpatched code first.)
- **Dispatch variant:** the same shape with a `GridWorkerDispatchComponent`-managed assignment; assert `AssignmentMatches` holds after load. Mutation: revert the dispatch re-claim → `RestoreState` returns `false` at `Persistence.cs:68-69` and the assignment is dropped.
- **Ghost-worker regression pin (must stay green):** keep the existing `:4686` assertion — a claim by `ghost_worker_123`, bound to no executor and no live actor, still loads `Queued` with empty `ClaimedBy`. This proves the re-claim did not resurrect orphan claims.

## Dependencies / collisions

- **ENH-12** (job-queue spatial claim index): the re-claim goes through `ClaimJob`/`TryReserveWorkCell`, which already maintain `_queuedIndex`/`_workCells`; no separate index touch is added, but coordinate if ENH-12 is reworking the claim/reserve entry points concurrently.
- **ENH-01** (typed `CellsChanged` / affected-chunks) and **ENH-02** (edit-kind classification): unrelated signal work; no overlap, but both were reference points for "restore must reach the consumer" — this fix follows the same "restore must re-assert the fact, not assume it survived" discipline.
- **`GameStateManagerComponent` restore ordering:** the fix depends on the queue restoring before the executor/dispatcher (jobs must exist for the re-claim). That order is currently conventional, not pinned (`GameStateManagerComponent.cs:445-450`). Pinning it is out of scope here; the guard constructs the working order. Flag if a concurrent session is editing `GameStateManagerComponent`'s phases.
- No direct file overlap with the streaming group (`TerrainWorldComponent`/streaming/archive) a separate session owns; this is entirely in `ecs/grid` job/worker files plus the shared `tests/GridPlacementSmoke.cs`.

## Out of scope

- Removing or renaming `RequeueClaimedJobsOnLoad` (owner's call).
- Pinning the queue-before-executor restore order in `GameStateManagerComponent` (a separate ordering-robustness item).
- The post-restore reconciliation phase alternative.
- Any change to how actor (non-world) workers restore — that path already re-claims correctly and is only cited as the pattern to mirror.
