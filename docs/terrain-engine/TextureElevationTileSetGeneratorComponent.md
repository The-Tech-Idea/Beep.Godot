# TextureElevationTileSetGeneratorComponent

Support utility: an offline/editor asset-generation tool that bakes a 2.5D "elevated" tile atlas from one or more source textures — it sits in the asset pipeline alongside `MountainPrefabGeneratorComponent`/`MountainTileMapLayerGeneratorComponent`, not in the procedural map-generation pipeline (`TerrainGeneratorComponent` and its `Terrain*Stage` files) and not in any runtime renderer.

`TextureElevationTileSetGeneratorComponent` is a `[Tool]` `Node` that builds a fixed 8×4-tile reference atlas (32 regions) where each region is tall enough to hold a walkable top face stacked over a cliff/wall face below it — covering top pieces, cliff/stack faces, ramps, stairs, and a drop-shadow tile. For each of a hardcoded `TileSpecs` table entry it either procedurally paints the region (sampling colour from a supplied top texture and optional cliff/cliff-column/side-cliff textures, tinted and detailed per `Scenario`, with generated noise-based cracks/grooves/outlines) or, in an alternate "forest reference sheet" mode, blits fixed pixel rectangles straight out of one specific pre-authored source image. The result is written out as a PNG atlas and, optionally, an embedded-texture Godot `TileSet` `.tres` and a JSON tile manifest (role/walkable/climbable/direction per tile), then an `AtlasGenerated` signal fires. It has no awareness of grid/world state — it produces art assets other components (or a hand-built scene) would consume.

## Public API

- `enum ElevationScenario { Hill, Mountain, Dune, Canyon, Snow, Volcano, Swamp }` — selects the colour tint/shading treatment applied while painting; `Hill` has no bespoke case in any of the scenario switches and always falls through to each method's generic `default` branch (Mountain gets its own case in some but not all of them).
- `[Signal] AtlasGeneratedEventHandler(string atlasPath)` — emitted once at the end of a successful `GenerateElevationTileSet()` or the reference-sheet passthrough path, carrying `OutputAtlasPath`.
- `[Export] string TopTexturePath` — required source texture for the walkable top surface; generation aborts (with a `GD.PushWarning`, returns `""`) if it can't be loaded.
- `[Export] string CliffTexturePath` — optional generic cliff-face source texture.
- `[Export] string CliffColumnTexturePath` — optional column-specific cliff texture; falls back to `CliffTexturePath`'s loaded image when blank.
- `[Export] string SideCliffTexturePath` — optional side-wall cliff texture; falls back to the resolved cliff-column image when blank.
- `[Export] string OutputAtlasPath` (default `res://addons/beep_game_builder_cs/generated/terrain/elevation_tileset.png`) — PNG write target for the composited atlas.
- `[Export] string OutputTileSetPath` (`*.tres`) — write target for the generated `TileSet` resource, used only when `SaveTileSetResource` is true.
- `[Export] string OutputManifestPath` (`*.json`) — write target for the tile manifest, used only when `SaveManifest` is true.
- `[ExportGroup("Generation")] ElevationScenario Scenario` — see above.
- `[Export] int TileWidth` (16–256, default 64), `int TopHeight` (16–256, default 48), `int CliffHeight` (8–256, default 48) — per-tile pixel dimensions; each region is `TileWidth × (TopHeight + CliffHeight)`.
- `[Export] bool SaveTileSetResource` (default true) / `bool SaveManifest` (default true) — gate whether the `.tres`/`.json` side-outputs are written after the atlas PNG.
- `[Export] bool GenerateOnReady` (default false) / `bool GenerateInEditor` (default false) — `_Ready()` defers a `GenerateElevationTileSet()` call only when `GenerateOnReady` is true and (outside the editor, or `GenerateInEditor` is also true).
- `[Export] bool UseDirectTextureSampling` (default true) — when true, top/cliff pixels are read directly (tiled/jittered) from the source texture instead of the "pick the best-scoring nearby pixel" material sampler; falls back to the material sampler only where the direct sample is transparent.
- `[Export] bool PreserveCliffSourceLayout` (default true) — when true and a cliff/cliff-column/side-cliff texture is supplied, cliff pixels are read verbatim from the configured source rect (`SampleSourceRegion`) instead of being procedurally shaded.
- `[Export] bool UseForestReferenceSheetLayout` (default false) — switches tile painting to blit fixed rectangles out of `TopTexturePath` (see `ForestReferenceSourceFor`) instead of procedural painting, for every `TileSpecs` id it has a mapping for.
- `[Export] bool PreserveReferenceSheetOutputLayout` (default false) — when combined with `UseForestReferenceSheetLayout`, skips the whole `TileSpecs`/atlas pipeline entirely and just re-saves `TopTexturePath` unchanged as the output "atlas", with a different hand-written manifest describing that source sheet's own regions.
- `[Export] float TextureRepeatsPerTile` (0.25–8, default 1.0) — UV tiling multiplier used only by `SampleDirectTexture`.
- `[ExportGroup("Source Rects")] Vector2I TopSourceOrigin/TopSourceSize` — sub-rect of `TopTexturePath` to sample from; honoured only when `UseDirectTextureSampling` is true (the material-sampler fallback path ignores them and always uses the whole image).
- `Vector2I CliffColumnSourceOrigin/CliffColumnSourceSize`, `Vector2I SideCliffSourceOrigin/SideCliffSourceSize` — sub-rects for the respective cliff textures; honoured whenever `PreserveCliffSourceLayout` is true (the default) or `UseDirectTextureSampling` is true.
- `[ExportGroup("Look")] float EdgeRoundness` (0–0.4, default 0.18), `float OrganicEdgeAmount` (0–0.35, default 0.055) — corner rounding and noise wobble applied to the top-face silhouette mask (`TopMask`).
- `[Export] float CliffShadeStrength` (0–1, default 0.30) — vertical darkening strength used by `ApplyCliffShading`; only reached when `PreserveCliffSourceLayout` is false or no cliff texture was supplied, so it is inert under the default configuration.
- `[Export] float TopHighlightStrength` (0–1, default 0.10), `float OutlineStrength` (0–1, default 0.18), `float DetailDensity` (0–1, default 0.45) — top-face highlight falloff, outline-pixel opacity, and per-scenario detail-texture strength.
- `[Export] int Seed` (default 27431) — seeds every deterministic hash/noise call (material sampling jitter, cracks, grooves, top-mask wobble).
- `override void _Ready()` — see `GenerateOnReady`/`GenerateInEditor` above.
- `override string[] _GetConfigurationWarnings()` — flags a blank `TopTexturePath`, a blank `OutputAtlasPath`, or a non-positive `TileWidth`/`TopHeight`/`CliffHeight`; does not check `OutputTileSetPath`/`OutputManifestPath` even though those can independently cause a silent no-op (see Notes).
- `string GenerateElevationTileSet()` — loads the source textures, paints all 32 `TileSpecs` entries into a new atlas `Image`, saves it as PNG, optionally saves the `TileSet` and manifest, rescans the editor filesystem when running in-editor, emits `AtlasGenerated`, and returns the atlas path (or `""` on load/save failure).
- `Godot.Collections.Array<Godot.Collections.Dictionary> GetTileManifest()` — returns the static `TileSpecs` table (id/role/atlas coords/walkable/climbable/direction) as Godot dictionaries, independent of whether generation has ever run; usable purely for introspection (e.g. by an editor dock).

## Dependencies

None. This file reads and writes nothing else under `addons/beep_game_builder_cs/ecs/terrain/` — no `GridCellDataComponent`, `TerrainGeneratorComponent`, `TerrainLayers`, or any other component in this batch is referenced. Its only inputs are the externally-supplied texture files named by `TopTexturePath`/`CliffTexturePath`/`CliffColumnTexturePath`/`SideCliffTexturePath` (not part of this addon's source), and its only outputs are the PNG/`.tres`/JSON files it writes to `OutputAtlasPath`/`OutputTileSetPath`/`OutputManifestPath`. A repo-wide search found no other `.cs` file in the addon referencing this class; it is used only by `tests/texture_elevation_tileset_generator_probe.gd` and by generated reference docs (`docs/ADDON_REFERENCE.md` etc.) — it is not instantiated by any generation-pipeline component or gameplay scene in this repo.

## Notes

- `ScenarioTopTint(Color)` (defined for all seven scenarios) is never called anywhere in the file — dead code. The top face's colour is therefore never scenario-tinted; only `AddTopDetails`'s per-scenario detail texture and the generic grain/highlight in `TopPixel` vary the top face by scenario, while cliffs/ramps/the fallback colour do get scenario tinting via `ScenarioGeneratedCliffColour`/`ScenarioRampColour`/`ScenarioFallbackColour`.
- `private static int Wrap(int value, int size)` is defined but has no call site in the file — dead code.
- `TopSourceOrigin`/`TopSourceSize` are exported and documented (via the `[ExportGroup("Source Rects")]` grouping) as sub-rect controls, but only take effect when `UseDirectTextureSampling` is true; with it false, `TopPixel` calls `SampleTopMaterial`, whose call chain always passes `Vector2I.Zero` for both origin and size (i.e. the whole image), silently ignoring whatever the user set — no warning either way.
- `CliffShadeStrength` (and the rest of `ApplyCliffShading`'s groove/ledge shading) only runs when `PreserveCliffSourceLayout` is false or no cliff texture was supplied; since `PreserveCliffSourceLayout` defaults to `true`, supplying any cliff texture (the expected/normal case) makes this exported strength value inert — cliffs instead get only a flat `AdjustBrightness` ledge darken.
- `UseForestReferenceSheetLayout` bypasses essentially the entire "Look" group (`EdgeRoundness`, `OrganicEdgeAmount`, `TopHighlightStrength`, `OutlineStrength`, `DetailDensity`) and all `Scenario` tinting for every tile id that `ForestReferenceSourceFor` maps (all of them except `cliff_shadow`) — it blits from hardcoded pixel rectangles (e.g. `Rect2I(320, 0, 128, 128)`) that assume `TopTexturePath` is laid out exactly like one specific pre-authored reference sheet. There is no validation that the loaded image actually matches that layout; a differently-laid-out image is silently sampled from the wrong regions rather than rejected.
- `GenerateElevationTileSet()` guards each side-output with `!string.IsNullOrWhiteSpace(OutputTileSetPath|OutputManifestPath)` before saving, but `_GetConfigurationWarnings()` never checks those two paths — leaving `SaveTileSetResource`/`SaveManifest` at their default `true` while clearing the corresponding output path silently skips that save with no warning surfaced anywhere.
- `SampleDirectTexture` computes local `width`/`height` from `source.GetWidth()/GetHeight()` (lines 893–894) and never uses either — `SourceRectFor` recomputes both internally; harmless but unused locals.
- Class-level doc comment ("not a flat autotile mask… reserves space for a walkable top surface plus cliffs, stacked walls, ramps, stairs, and shadows") accurately describes the `TileRole`/`TileSpecs` table beneath it.
